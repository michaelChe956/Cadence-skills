## 4. 页面与 API 映射

### 4.1 已匹配接口

| PAGE ID | API ID | 分类 | 方法与标准路径 | 调用位置 | 请求封装、Store 或 Hook | 接口主文件 | SERVICE/MODULE | 状态 | 可信度 | 证据 |
|---------|--------|------|----------------|----------|-------------------------|------------|----------------|------|--------|------|

填写规则：

- `API ID` 必须与 `cadence/knowledge-base/interfaces/README.md` 和接口主文件一致。
- `接口主文件` 必须使用 Markdown 相对链接，目标位于 `../interfaces/`；不能只写文件名或 API ID。
- `方法与标准路径` 必须包含 HTTP Method，以及合并 baseURL、代理、网关和动态参数模板后的标准路径。
- 页面经 Store、Hook、Composable、Thunk 或 Service 间接调用时，在“请求封装、Store 或 Hook”中写出完整前端调用链。
- 同一页面调用多个 API 时逐条记录，不能用逗号合并成一个无法追踪的单元格。

### 4.2 页面字段与数据模型影响

| PAGE/ROUTE ID | API ID | SERVICE/MODULE | TABLE 稳定 ID | 页面字段 | API 字段来源 | 表字段 | 读写 | Mapper/SQL 或后端映射 | 证据状态 | 表文档链接 |
|---------------|--------|----------------|---------------|----------|------------|--------|------|----------------------|----------|------------|
| {PAGE-ID} | {API-ID} | {SERVICE-ID} | {TABLE-ID} | {展示/筛选/提交字段} | {请求/响应模型与前端映射} | {字段} | {R/W} | {符号或SQL} | {已确认/待确认} | [`{TABLE-ID}`](../data-models/{路径}.md) |

页面字段必须沿 `PAGE → API 模型/请求代码 → SERVICE/MODULE → Mapper/SQL → TABLE 字段` 逐跳取证。页面、API 与表字段同名不能作为关系证据；缺少任一关键跳时标记“待确认”。

### 4.3 页面配置依赖

| PAGE/ROUTE ID | API ID 或前端绑定 | 配置组稳定 ID | 服务配置实体 | 配置键 | 页面影响 | 环境/Profile | 生效条件与绑定 | 证据状态 | 配置文档链接 |
|---------------|-------------------|----------------|--------------|--------|----------|--------------|--------------|----------|--------------|
| {PAGE-ID} | {API-ID或代码绑定} | {CONFIG-ID} | {SERVICE-ID} | {配置键} | {路由/权限/请求/展示/Feature Flag} | {环境/Profile或待确认} | {条件与绑定位置} | {已确认/待确认} | [`{SERVICE-ID}`](../configurations/{服务文档}.md) |

Feature Flag、环境变量和菜单配置只有在能够证明直接控制页面、路由、权限、请求或展示行为时才记录。敏感值统一写 `<redacted>`；缺少绑定或生效条件时写“待确认”。

### 4.4 未匹配接口候选

| PAGE ID | 候选 API ID | 已知方法与路径 | 调用位置 | 接口主文件 | 状态 | 可信度 | 待确认项 |
|---------|-------------|----------------|----------|------------|------|--------|----------|

未在接口索引中找到唯一匹配项时：

- 使用 `API-CANDIDATE-*` 作为临时追踪 ID。
- `接口主文件` 填写“未登记”，不生成不存在的 Markdown 链接。
- 记录已知 Method、Path、调用位置和候选后端入口。
- 将核实任务写入 `open-questions.md`，交由 `knowledge-base-api` 补录或校对。

## 11. 完整追溯关系

```text
ROUTE
→ PAGE
→ API
→ SERVICE/MODULE
├─ TABLE → 字段/Mapper/SQL → data-models/ 文档
└─ CONFIGURATION → 配置键/环境/生效条件 → configurations/ 文档
```

API 节点必须使用与接口知识库相同的稳定 ID，并链接到对应接口主文件。TABLE 与 CONFIGURATION 关系必须经过 API 和 SERVICE/MODULE 证据，不能由页面字段或业务名称直接推断。
