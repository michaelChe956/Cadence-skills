# 典型场景

## 1. 目标目录只有部分输入文件

`cadence/knowledge-base/user-input/base-info.md` 已存在，其余 8 个文件缺失。

处理结果：

1. 门禁 1 判定为“部分存在”。
2. 只生成缺失的 8 个文件，`base-info.md` 保持原样，不读改、不覆盖。
3. 输出中分别列出已存在文件与新生成文件。
4. 若 `base-info.md` 已声明的六领域状态与新生成文件冲突，在确认清单中列为待确认项，不擅自改写 `base-info.md`。

## 2. 目标目录已有完整输入

9 个文件全部存在。

处理结果：

1. 门禁 1 判定为“全部存在”，立即停止，不写任何文件。
2. 报告已有文件清单，建议改用 `/knowledge-base-bootstrap` 校验输入并初始化。

## 2a. 目标目录是复制过来但未填写的模板

9 个文件都存在，但内容仍是插件模板的原始占位：基线信息字段为空、状态是模板默认的 `全量`、示例行与填写提示仍在。

处理结果：

1. 门禁 1 判定为“未填写的模板占位”，视为输入尚未准备，允许生成草稿覆盖。
2. 报告中标明覆盖了哪些占位文件（例如 `base-info.md`、`api-scope.md` …），便于用户核对没有丢内容。
3. 若同一目录中有个别文件已填写（基线信息非空或状态被改过），该文件仍按“已填写”处理，不被覆盖。

## 2b. 规划文档里的能力尚未实现

`docs/issue-003-公告管理升级.md` 规划了分类 CRUD、详情、编辑、删除、置顶、分页筛选，但当前代码只有列表与创建。

处理结果：

1. `api-scope.md` 的已实现清单只登记代码中存在的入口。
2. 规划项写在清单后的说明段落，标注“规划中未实现”，交用户裁决是否纳入本次知识库范围。
3. 不把规划项登记为已实现能力，也不因此判定接口领域不适用。

## 3. 知识库已经初始化过

目标项目已有 `cadence/knowledge-base/manifest.yaml`。

处理结果：

1. 门禁 2 命中，立即停止，不创建 `user-input/`，不生成任何草稿。
2. 报告已存在的固定产物，引导 `/knowledge-base-bootstrap` 续跑或 `/knowledge-base-context` 查询、`/knowledge-base-update` 更新。

## 4. 没有前端工程

目标项目只有 Java 后端。

处理结果：

1. 页面状态写 `不适用`，原因写“目标项目未发现 Vue/React 前端工程”。
2. 不生成 `page-scope.md`，并从 `base-info.md` 删除页面的资料链接，不留失效链接。
3. 其余五个领域按证据正常生成。
4. 在 `base-info.md` 分析说明中写明“目标项目为纯后端形态”。

## 5. 没有 DDL

项目只有 Entity 与 Mapper XML，没有建表脚本。

处理结果：

1. `database-ddl.sql` 仍生成，只写“未找到权威 DDL，结构证据见 data-model-scope.md”。
2. `data-model-scope.md` 登记 Entity、Mapper XML 等结构证据及其路径，数据模型状态为 `全量`。
3. 不编造表结构，不把 Mapper XML 当成 DDL。

## 6. 配置只有本地工作目录

目标项目只有 `src/main/resources/application.yml`，没有固定提交、标签或导出快照。

处理结果：

1. 配置状态写 `不适用`，原因写明“本地工作目录不是锁定发布批次的不可变快照，需要用户指定锁定批次或导出快照”。
2. `configuration-scope.md` 仍生成，记录配置目录、纳入文件数量、服务摘要与文件规则摘要，作为证据记录，`base-info.md` 保留资料链接。
3. 确认清单中列为高优先级待确认项：用户提供不可变快照目录后改为 `全量` 或 `指定`。

## 7. 对外能力无法从代码判断

工程里有 3 个 REST 控制器，无法判断哪些真正对外。

处理结果：

1. `api-scope.md` 列出全部 3 个入口，状态列写 `待确认`。
2. 文件内提示用户逐项裁决对外属性。
3. 不擅自判定对外或对内——契约规定未登记的能力归入对内能力，擅自缩小清单会丢失对外能力。

## 8. 结构证据冲突

同一张表在两个 SQL 文件中定义不一致。

处理结果：

1. `data-model-scope.md` 两处证据都登记，来源类型如实标注。
2. 冲突写入确认清单交用户裁决，不在草稿阶段择一。
3. 不停止生成——冲突不阻断其余字段的草稿产出。

## 9. 检测到敏感值

配置证据里出现明文 Token。

处理结果：

1. 停止写入含该敏感值的文件，报告文件位置。
2. 敏感值不落盘；该字段改写为 `<redacted>` 并在确认清单中提示用户补充脱敏版本。
3. 其余文件继续生成。

## 10. 项目形态不匹配

目标项目既无 Java 构建特征也无前端 `package.json`。

处理结果：

1. 门禁 3 命中，立即停止，不创建 `cadence/knowledge-base/` 目录。
2. 报告目标项目形态与该 Skill 的适用范围差异，建议改用 `/legacy-bootstrap` 或先确认目标项目形态。
