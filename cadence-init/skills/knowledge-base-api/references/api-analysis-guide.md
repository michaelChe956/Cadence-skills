# API 与集成能力分析指南

## Schema 4.0 前置契约

只接受 `cadence/knowledge-base/manifest.yaml` 中的 `schema_version: "4.0"`，并以 Manifest 的工程、API、数据模型和配置授权范围为边界。Manifest 缺失、版本不是 4.0 或领域未授权时停止；不得兼容旧版或回退到全仓扫描。

分析前读取 Base Info 关系矩阵、`data-models/README.md`、目标 TABLE 字段级文档、`configurations/README.md` 和目标服务配置实体。索引提供导航，字段和配置结论必须回到对应文档与代码证据。

## 分析顺序

```text
读取 Manifest 与对外能力清单
→ 建立项目级能力索引
→ 区分对外与对内
→ 核实实现状态与调用链
→ 关联字段级 TABLE 与直接配置依赖
→ 生成主文件和可选配套文件
→ 更新证据、关系和待确认项
```

## 对外分类

用户 `api-scope.md` 是全部对外能力的权威清单。清单用于分类，代码用于实现验证：

- 清单有、代码有：对外能力，记录当前状态。
- 清单有、代码未定位：仍是对外能力，状态待确认。
- 清单无、代码发现：归为对内能力。
- 清单与代码名称冲突：保留清单分类，记录候选实现和冲突。

## 对外 API 与对内 REST

| 维度 | 对外 API | 对内 REST |
|------|----------|-----------|
| 分类依据 | 用户 `api-scope.md` 的对外能力清单 | 工程范围内发现且未登记在对外清单 |
| 典型调用方 | 合作方、外围系统、开放平台消费者 | 页面、管理端、BFF、内部系统或服务 |
| 入口分析重点 | 开放网关、能力编码、协议转换、Provider、外部鉴权和限流 | 请求封装、代理或 BFF、Controller/Router、登录态和内部权限 |
| 代码未定位 | 仍保持对外，状态待确认 | 记录候选、状态未知或不可达 |
| 页面关联 | 只有前端代码确实调用该对外地址时关联 | 页面能力分析的主要 REST 关联对象 |
| 成品案例 | `demo.md`、`demo_参数与报文.md` | `demo_对内REST.md`、`demo_对内REST_参数与报文.md` |

两类能力可以使用相同的 11 节主文件模板，但分类证据、调用方、入口、鉴权、暴露方式和页面关系不能互相替换。

## 全量发现

全量模式不得只扫描 Controller。至少检查：

| 能力类型 | 常见入口 |
|----------|----------|
| REST | Controller、Router、网关和自定义路由 |
| 服务间 HTTP | Feign、WebClient、RestTemplate、自定义 Client |
| RPC | Provider、Consumer、注册与装配配置 |
| 消息 | Producer、Listener、Consumer、Topic 与 Group |
| Redis 队列 | Pub/Sub、Stream、List、阻塞消费 |
| 文件 | FTP、SFTP、对象存储、上传下载与批量交换 |
| 任务 | Scheduled、Quartz、XXL-JOB、Batch、自定义调度 |

先完成索引，再逐项深挖，避免被某个 Demo 或入口类型限制范围。

## 指定深挖

指定模式只分析用户列出的能力和必要内部依赖。内部依赖只作为调用链节点，不自动扩展为新的执行任务。

## 调用链核实

每项能力核实：

1. 入口定义、实现、装配和暴露状态
2. 请求、响应、消息或文件模型
3. 鉴权、权限、租户和环境条件
4. Service、DAO、RPC、消息和任务调用
5. 分支、开关、重试、幂等和失败处理
6. 表、缓存、中间件、文件和外部系统副作用

直接引用为空不能证明能力未使用。遇到封装、工厂、代理或多层转发时逐跳追踪，并为结论提供文件与行号。

每个 API 固定输出两条关系链：

```text
API → SERVICE/MODULE → TABLE → 字段/Mapper/SQL
API → SERVICE/MODULE → CONFIGURATION → 配置键/生效条件
```

服务或模块优先引用 Base Info 稳定 ID。直接 SQL、框架代理或跨服务访问仍需保留实际中间节点；节点无法确认时写 `待确认`，不得为凑齐链路补造服务。

## 数据库证据

证据来源仅包括：

- 用户 DDL
- Entity、Mapper、SQL 和迁移文件
- 数据源、Schema 和 Profile 配置
- 用户明确说明

禁止连接数据库和查询在线元数据。表名必须落到 SQL 或 DDL；Schema 无法确认时填写待确认，不使用工程名代替。

## 字段级数据影响

1. 从 Service/Module 的 Mapper、SQL、Entity、Assembler 和模型转换定位 TABLE 稳定 ID。
2. 链接 `data-models/` 中的字段级表文档，记录当前 API 的读写类型和涉及字段。
3. `表字段证据状态` 只描述字段定义来自 DDL、迁移、代码推导、用户提供、来源冲突或待确认。
4. `端到端映射状态` 单独核对 `API 模型 → SERVICE/MODULE → Mapper/SQL → TABLE 字段`；请求/响应字段到表字段必须由转换代码、Mapper 或 SQL 逐跳证明，字段同名不是证据。
5. 只摘录当前 API 直接读写或用于条件、排序、鉴权、路由和副作用的字段，不复制完整表结构。
6. 表文档、代码和 DDL 冲突时保留各侧结论。DDL 或迁移已确认只能确认表字段证据；缺少下游服务 Mapper/SQL、转换代码或任一关键跳时，端到端映射状态必须写 `待确认`。

## 配置依赖

从 API 入口和 Service/Module 沿属性绑定、条件装配、网关、鉴权过滤器、中间件或外部系统客户端定位配置。只有直接影响请求、响应、副作用、路由、鉴权、中间件或外部系统的配置进入文档。

每项依赖记录：配置组稳定 ID、服务配置实体、配置键、环境/Profile、绑定位置、生效条件、证据状态和 `configurations/` 文档链接。配置键存在不等于当前环境生效；缺少加载顺序、绑定或条件证据时写 `待确认`。

密码、Token、AccessKey、Secret、密钥、私钥、完整连接串、内部域名、IP 和 URL 的值统一写 `<redacted>`，Demo 和成品均不得写真实环境值。

## 工具分工

| 场景 | 优先工具 |
|------|----------|
| 跨文件调用链、影响面和功能流向 | CodeGraph |
| 单文件类、函数、成员和导入导出 | `ast-grep outline` |
| 已知符号、注解、配置键和字面值 | 文本检索与定向读取 |
| 工具不可用 | 文本检索定位候选，再定向阅读 |

Mapper XML 和配置文件位置必须先探测项目结构，不套用其他项目的目录约定。

## 证据可信度

| 可信度 | 判定 |
|--------|------|
| 高 | 用户清单、实现、装配和调用证据相互支持 |
| 中 | 缺少装配、调用方或环境证据 |
| 低 | 只有声明、名称候选或存在来源冲突 |

## 常见误判

- Controller 存在等于对外 API
- 用对内 REST Demo 取代对外能力清单中的接口案例
- 业务名称相似就把页面 REST 关联到对外开放能力
- 未在用户清单中的接口自动判为对外
- 依赖存在等于消息或 RPC 已使用
- 同 JVM Bean 等于网络 RPC
- DAO 名称等于实际表名
- API 模型字段与表字段同名等于存在映射
- 同一服务配置文件中的键都影响当前 API
- 配置键存在或有默认值等于目标环境已生效
- 默认配置等于所有环境有效
- 本地缓存等于没有数据库来源
- Demo 中出现的技术栈等于目标项目必然使用
