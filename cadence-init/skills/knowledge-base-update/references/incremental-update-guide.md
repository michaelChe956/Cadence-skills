# KnowledgeBase 增量更新指南

## 目录

- 变更边界
- 影响映射
- 稳定 ID
- 人工内容
- Schema 迁移
- 无 Git 模式
- 常见误判

## 变更边界

优先使用用户指定起止提交。没有指定时使用 manifest 的基线提交到当前 HEAD，并把工作区未提交差异作为独立范围记录。

多仓项目为每个仓库分别记录分支和基线，不使用一个提交 SHA 表示全部仓库。

## 影响映射

### Java

| 变更 | 常见影响 |
|------|----------|
| Controller 路径或参数 | API、页面调用、网关和概览 |
| Service 事务或逻辑 | API 副作用、流程、表和事件 |
| Entity、Mapper、SQL | 数据模型、API 和页面字段 |
| Security、Gateway | API 暴露和权限 |
| Producer、Listener | 消息能力、流程和幂等 |
| 配置绑定类 | 配置、Profile 和条件启用 |

### Vue/React

| 变更 | 常见影响 |
|------|----------|
| 路由配置 | 页面树、导航和权限 |
| 页面组件 | 页面操作和 API 调用 |
| API 模块 | 页面映射和后端 API |
| Store、Hook、Composable | 权限、动态路由和数据流 |
| 代理或环境变量 | API 完整路径和环境差异 |

### DDL 与配置

DDL 字段变更需要检查 Entity、DTO、Mapper、API 模型和页面表单。配置变化需要检查绑定类、条件装配、运行环境和开发指南。

## 稳定 ID

优先以业务语义和既有实体关系判断同一性，不仅依赖文件路径。重命名需要至少一个直接证据或多个相互支持的间接证据。

## 人工内容

允许更新：

- 稳定管理区块
- 明确标记自动生成的表格行
- manifest 和机器维护索引

禁止更新：

- 用户自由文本说明
- 管理标记之外的章节
- 用户确认结论，除非新证据产生冲突并保留双方

## Schema 迁移

迁移说明至少包含：

- 当前版本和目标版本
- 字段、目录和标记变化
- 自动迁移范围
- 人工内容保护方式
- 回退方式
- 不能自动迁移的项目

## 无 Git 模式

使用文件路径和用户变更清单时，删除、移动和重命名的可信度降低。不得用文件时间戳单独证明业务变更顺序。

## 常见误判

- 文件移动等于删除和新增
- 类改名等于业务能力变化
- DDL 文件新增等于数据库已部署
- 配置键存在等于所有环境生效
- 路由删除等于页面组件也已删除
- API 文档更新等于实现已经同步
- Git 无差异等于外部配置和数据库无变化
