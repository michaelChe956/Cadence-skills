# KnowledgeBase 增量更新指南

## 输入边界

增量更新只接受 Manifest 4.0，并且必须显式指定唯一变更包：

```text
cadence/knowledge-base/user-input/updates/CHANGE-变更标识/
```

目标目录中的 `change-summary.md`、`code-change.md`、`database-change.md`、`configuration-change.md` 和 `verification.md` 五份文档全部强制存在。任何文档缺失、字段为空、状态冲突或无变更声明缺少判断依据时停止。

数据库和配置文档始终必需。无数据库或配置变化时也要完整填写字段、验证范围和无变更判断依据。模板位于 `cadence-init/skills/knowledge-base-update/user-input/change-package/`。

## 影响链

更新必须沿以下链路建立可审计映射：

```text
变更包 → MR/提交 → 变更文件与符号 → 稳定 ID → 数据模型/配置/API/页面 → 受影响文档
```

中间件和领域规则也挂接到稳定 ID 与关系矩阵。无法确定影响时只扩大到所属模块，不扩大到变更包、Manifest 或工程清单之外。

## 代码范围验证

代码有变更时，Merge Request 地址或编号、源分支、目标分支、起始提交、结束提交、修改工程、修改文件与符号及本地可验证范围全部强制。起止提交必须可在本地解析，且验证范围必须与 MR 和分支声明一致。

Git Diff 和代码扫描只能验证包内代码声明，不能推断或替代缺失的 MR、分支、提交、文件和符号字段。工作区差异不等于 MR 完整范围，也不能用当前 `HEAD` 擅自补齐结束提交。

## 数据库资料验证

数据库文档必须覆盖数据库或 Schema、逻辑表、字段、索引、约束、DDL 或迁移路径、上线状态、兼容性和回滚方式。DDL 与迁移只作为只读证据，不能替代 `database-change.md`，也不得执行。

代码中的持久化字段、Mapper 或 SQL 变化与数据库无变更声明冲突时停止。只有包内提供可定位证据证明该变化不影响持久化结构时，才能保留无变更结论。

## 配置快照验证

`configuration-change.md` 必须提供同一环境的基线和目标快照标识、发布批次、生成或获取时间、来源类型、两个可读外部目录、两个最终快照指纹、共同纳入文件范围、涉及服务、配置组和已知差异。

基线标识、环境、发布批次、生成或获取时间、来源类型、目录、指纹和纳入范围必须与 Manifest 的 `evidence.configuration_snapshots.baseline` 和 `scope.configurations` 授权一致。目标快照不得扩大环境、服务或文件范围。比较前后按 Manifest 4.0 固定算法验证指纹；快照目录变化、指纹不匹配或范围越界时停止。

配置声明无变化时，目标快照仍必须存在。如果目标与基线的纳入文件或指纹存在差异，不能继续沿用“无变更”，必须停止并返回冲突及影响。Git 无差异不能证明外部配置无变化。

快照比较只能验证 `configuration-change.md`，不能替代它。不得连接配置中心、执行部署脚本或把外部快照复制到 KnowledgeBase。

## 稳定 ID

优先以业务语义和既有关系判断实体同一性，不只依赖路径：

- 新增：创建稳定 ID 并登记来源。
- 修改：保留 ID，更新属性、状态和证据。
- 移动：业务语义不变时保留 ID，只改来源路径。
- 重命名：证据充分时保留 ID 或登记旧新映射。
- 删除：移出活动清单，但保留删除证据、旧关系和历史。

来源不足或相互冲突时停止，不通过猜测合并实体。

## 人工内容

允许更新稳定管理区块、明确的自动生成表格、Manifest 和机器维护索引。禁止覆盖管理标记之外的自由文本、人工确认结论和历史说明。新证据与人工结论冲突时保留双方，并登记来源冲突。

## 幂等处理

以变更标识及包内文件相对路径和内容 SHA-256 有序清单生成幂等标识。执行前后都检查 Manifest 的 `update.processed_packages`：

- 相同变更标识和幂等标识已存在：直接报告已处理，不更新文档或历史。
- 相同变更标识但幂等标识不同：按已处理包被修改处理，停止并登记冲突。
- 新包：成功后把标识写入 `processed_packages`，并同步 `last_change_package`。

配置有变化时，验证后的目标快照成为新的 Manifest 配置基线；无变化时保留原基线。相同包不得重复历史、重复实体或重复稳定 ID 映射。

## 停止响应

输入缺失或冲突时，一次性返回目标补齐目录、插件模板目录、缺失文档或字段、具体影响和重新执行方式。停止后不得扫描未授权范围或生成半成品。

## 常见误判

- Git Diff 可以替代完整变更包。
- MR 地址可以替代本地可验证提交范围。
- DDL 文件存在等于数据库已经上线。
- 数据库无 DDL 等于数据模型无变化。
- Git 无差异等于外部配置无变化。
- 配置键相同等于两个环境快照一致。
- 同一个 `CHANGE-*` 目录内容被修改后仍可当作原包重放。
- 文件移动等于业务实体删除后新增。
