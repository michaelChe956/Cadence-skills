# KnowledgeBase 增量更新

## 概述

以现有知识库、Git 基线和用户提供的增量资料为输入，识别受影响实体与关系，只更新相关文档和技能管理内容。保护人工内容，保留删除与重命名历史，不把增量更新退化为无差别全量重写。

## 必读资源

- 执行前读取 `references/incremental-update-guide.md`。
- 更新变更历史时使用 `assets/change-history-template.md`。
- 需要参考综合变更场景时读取 `references/demo.md`。

## 前置条件

优先读取：

- `cadence/knowledge-base/manifest.yaml`（必须为 Schema 3.0）
- `cadence/knowledge-base/change-history.md`
- `cadence/knowledge-base/evidence/traceability-matrix.md`
- `cadence/knowledge-base/open-questions.md`
- 当前 Git 分支、提交和工作区状态
- 用户提供的增量 DDL、配置、中间件、API、路由和领域资料

如果知识库不存在、Manifest 缺失或 Schema 不是 3.0，停止增量流程并引导使用 `knowledge-base-bootstrap` 全量建立当前 Schema。不得迁移或覆盖旧版知识库。

## 强制规则

- 先确认知识库 Schema 版本、生成技能版本和 Git 基线。
- 记录当前分支，禁止混合其他分支的变更。
- 识别新增、修改、删除、移动、重命名和条件启用变化。
- 从变更文件定位符号，再通过稳定 ID 和关系矩阵确定受影响文档。
- 只更新自动管理章节，保留管理标记之外的人工内容。
- 删除活动能力时保留变更历史和旧 ID 映射。
- 相同基线与相同变更重复执行不得产生重复记录。
- 来源冲突必须进入待确认清单。
- 工作区存在未提交修改时不得清理、覆盖或恢复用户文件。

## 用户增量输入

引导用户提供：

1. 变更 DDL 或迁移文件。
2. 新增、修改或删除的配置项及环境。
3. 中间件、Topic、Queue、Consumer Group 或版本变化。
4. API 文档变化和对外范围变化。
5. 页面、路由、菜单和权限变化。
6. 领域术语和业务规则变化。
7. 已知变更范围、版本号或 Git 起止提交。

用户未提供的部分根据 Git 差异分析，但必须标记来源。

## 工作流程

### 1. 读取基线

从 manifest 获取：

- Schema 版本
- 生成技能版本
- Git 分支
- 基线提交
- 上次执行模式
- 已登记仓库、服务、模块和文档
- 输入资料状态

manifest 缺少基线时，允许用户指定起点；无法确定时不得假设某个历史提交。

### 2. 检查 Schema 3.0

- Manifest 为 Schema 3.0：继续增量更新。
- Manifest 缺失或不是 Schema 3.0：停止，不执行自动迁移或覆盖。
- 需要旧知识库内容时，由用户人工确认后另行整理，不属于本技能范围。

### 3. 收集变更

读取 Git 基线到当前提交的差异，并合并工作区未提交变更与用户增量资料。区分：

- 新增文件和符号
- 修改文件和符号
- 删除文件和符号
- 文件移动
- 类、方法、路由、表或配置重命名
- 依赖、版本和 Profile 变化
- 文档、DDL、配置与代码冲突

不得执行 `reset`、`checkout --`、`clean` 或其他破坏性命令。

### 4. 建立影响映射

使用：

```text
变更文件 → 变更符号 → 稳定实体 ID → 关系矩阵 → 受影响文档
```

典型映射：

- Controller 或 RPC 变化 → API、页面、概览
- Service 变化 → API、流程、数据和中间件
- DDL 或 Mapper 变化 → 基础信息、API、页面影响关系
- 配置变化 → 基础信息、开发指南、API 暴露或中间件状态
- 路由或页面变化 → 页面、概览、API 调用方
- Topic 或 Listener 变化 → 中间件、API 能力和业务流程
- 术语变化 → 术语表、概览和相关领域描述

无法从关系矩阵确定影响时，扩大到所属模块，不扩大到无关全仓。

### 5. 处理稳定 ID

#### 新增

生成新的稳定 ID，登记来源和关系。

#### 修改

保留 ID，只更新属性、状态和证据。

#### 移动

路径变化但业务实体未变时保留 ID，更新来源路径。

#### 重命名

能够证明同一业务实体时保留 ID 或记录旧 ID 到新 ID 映射；证据不足时保留两条候选并待确认。

#### 删除

从活动清单移除，在变更历史记录删除时间、原因证据和受影响关系。不得直接抹除历史。

### 6. 更新领域文档

按影响范围调用：

- `knowledge-base-base-info`
- `knowledge-base-api`
- `knowledge-base-pages`
- `knowledge-base-overview`

向领域技能传递具体实体 ID、变更文件和目标章节，禁止要求其重新分析不相关项目范围。

### 7. 保护人工内容

区分：

- 自动生成章节
- 人工维护章节
- 待确认章节
- 历史记录

只更新稳定管理标记或明确的自动生成表格。没有管理边界时，生成建议差异或新文件，不直接覆盖整份人工文档。

### 8. 更新变更历史

记录：

- 更新时间
- 起止提交或无 Git 模式
- 用户提供的增量资料
- 变更实体 ID
- 受影响文档
- 新增、修改、删除、移动和重命名
- 来源冲突和待确认项
- Schema 版本校验结果

相同起止提交和相同变更实体不得重复追加。

### 9. 更新 manifest

更新：

- 新基线提交
- 文档更新时间
- 输入资料状态
- 覆盖数量
- 待确认项数量
- 稳定 ID 映射
- Schema 与技能版本

只有分母明确时才能更新覆盖率。

### 10. 输出报告

向用户报告：

- 基线与当前提交
- 已分析变更范围
- 更新文档
- 新增、修改、删除和重命名实体
- 保留的人工内容
- 来源冲突与待确认项
- 未覆盖变更和原因

## 无 Git 降级

没有 Git 仓库时：

1. 使用用户变更清单。
2. 对比现有知识库来源路径与当前文件。
3. 使用用户提供的增量 DDL、配置和文档。
4. 明确无法可靠识别历史删除、移动和重命名。
5. 不声称完成完整影响分析。

## 禁止行为

- 不无差别重写整个知识库。
- 不删除管理边界之外的人工内容。
- 不把文件移动误判成能力删除和新增。
- 不把删除文件当成暂时无法扫描而保留活动状态。
- 不在不同 Git 分支之间合并知识事实。
- 不迁移或自动升级旧版知识库 Schema。
- 不提交、推送或清理用户工作区，除非用户明确要求。

## 完成条件

- 基线、当前提交和变更范围明确。
- 每个更新文档都能追溯到变更实体。
- 稳定 ID、关系矩阵和来源路径同步更新。
- 删除和重命名保留历史。
- 人工内容未被覆盖。
- 相同变更重复执行不会产生重复记录。
- 未覆盖范围和待确认项已经报告。
