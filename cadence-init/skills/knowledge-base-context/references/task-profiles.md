# 固定任务画像

每次选择一个主画像，可附加最多两个辅助画像。画像只决定读取重点与输出字段，不执行下游任务。

## 画像选择

| 画像 | 识别信号 | KnowledgeBase 必读 | 当前实现必读 | 专属输出 |
|------|----------|--------------------|--------------|----------|
| 需求澄清 | 澄清、范围、边界、规则、已有能力、是否支持 | 项目概览、术语、页面、对外能力、核心流程、待确认项 | 状态枚举、校验、入口、业务分支、Feature Flag | 已有能力、系统边界、业务规则、冲突、澄清问题 |
| Design | 设计、方案、架构、接口设计、数据模型、技术选型 | 服务、API、数据模型、中间件、横切机制、关系矩阵 | 架构、实现入口、配置装配、扩展点、技术约束 | 现状架构、可复用能力、约束、影响面、设计风险 |
| Plan | 计划、拆解、步骤、排期、实施顺序、改哪些文件 | 关系矩阵、开发指南、变更历史、相关领域文档 | 文件与符号依赖、测试入口、构建结构、修改边界 | 变更单元、依赖顺序、文件范围、风险、验证入口 |
| Coding | 实现、修改、重构、补代码、接入、开发 | 精确实体、API 报文、数据结构、证据索引 | 类、方法、SQL、配置、调用链、已有测试 | 修改入口、现有模式、边界条件、影响调用方、验证命令 |
| Testing | 测试、用例、覆盖、回归、断言、Mock、Fixture | API 报文、业务分支、错误码、数据约束、开发指南 | 测试框架、已有测试、Fixture、Mock、异常与边界实现 | 测试场景、数据准备、断言依据、回归范围、执行命令 |
| Review | 评审、审查、Diff、遗漏、风险、是否符合 | 需求实体、关系矩阵、变更历史、知识库约束 | Git Diff、修改符号、直接调用方、测试、配置变化 | 需求符合度、遗漏影响、回归风险、证据缺口、知识库漂移 |
| Debug | 定位、排查、错误、异常、不生效、失败、性能问题 | 核心流程、错误码、中间件、状态流转、待确认项 | 失败路径、日志位置、开关、异常、并发、数据访问 | 症状事实、调用路径、候选根因、验证入口、冲突证据 |

## 组合规则

- “实现并补测试”：主画像 `Coding`，辅助画像 `Testing`。
- “评审方案是否可落地”：主画像 `Review`，辅助画像 `Design`。
- “排查问题并制定修复步骤”：主画像 `Debug`，辅助画像 `Plan`。
- 用户明确交付物优先决定主画像；背景动作只作为辅助画像。
- 多个画像都可能成立但读取方向差异不大时，选择最接近最终交付物的画像，不提问。
- 只有不同选择会显著改变工程范围、实体或证据深度时才询问。

## 需求澄清

扩展条件：术语在多个模块含义不同、现有流程边界不清、业务规则只存在于代码分支。

停止条件：已明确已有能力、系统内外边界、关键规则、限制、冲突和必须由用户回答的问题。

## Design

扩展条件：设计需要复用或变更跨模块能力、事务边界、异步链路、数据模型或安全机制。

停止条件：已覆盖现状架构、可复用点、接口与数据约束、主要影响面和设计风险。

## Plan

扩展条件：文件修改存在先后依赖、多个工程需要协同、验证入口或回滚边界不明确。

停止条件：变更单元可独立验证，依赖顺序、文件范围、风险和命令明确。

## Coding

扩展条件：现有模式、参数约束、异常分支、数据副作用或测试入口缺失。

停止条件：精确修改入口、直接调用方、边界条件、既有模式和验证命令齐全。

## Testing

扩展条件：关键分支没有断言依据、测试数据来源不明、外部依赖隔离方式不清或回归范围未知。

停止条件：正常、异常、边界、权限、幂等或并发等相关场景有证据，数据准备和执行命令明确。

## Review

扩展条件：Diff 影响公共契约、配置、数据库、异步链路或未覆盖调用方。

停止条件：需求符合度、直接和必要间接影响、测试充分性、回归风险及知识库漂移均有结论。

## Debug

扩展条件：症状可由多个入口、开关、并发、数据状态或中间件路径解释。

停止条件：事实与假设分离，候选根因按证据排序，每个高优先级根因有安全验证入口。
