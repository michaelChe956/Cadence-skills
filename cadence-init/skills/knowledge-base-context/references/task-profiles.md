# Schema 4.0 固定任务画像

每次选择一个主画像，可附加最多两个辅助画像。画像只决定四类证据的读取重点与输出字段，不执行下游任务。每个画像都必须检查表关系和配置关系；没有直接关系时记录后停止对应方向。

## 组合规则

- “实现并补测试”：主画像 `Coding`，辅助画像 `Testing`。
- “评审方案是否可落地”：主画像 `Review`，辅助画像 `Design`。
- “排查问题并制定修复步骤”：主画像 `Debug`，辅助画像 `Plan`。
- 用户明确交付物优先决定主画像；背景动作只作为辅助画像。
- 只有不同选择会显著改变工程范围、实体或证据深度时才询问。

## 需求澄清

扩展条件：数据能力、字段约束、环境开关或现有流程边界不清。

停止条件：已有能力、系统内外边界、逻辑表与字段限制、目标环境开关、关键冲突和必须由用户回答的问题明确。

## Design

扩展条件：方案需要变更跨模块能力、事务边界、表结构、数据源、Profile 或 Feature Flag。

停止条件：现状架构、表与字段约束、数据源路由、配置加载和生效条件、主要影响面与设计风险明确。

## Plan

扩展条件：Mapper/SQL、字段映射、迁移顺序、配置键、目标环境或验证入口不明确。

停止条件：变更单元可独立验证，代码、数据模型、配置步骤及依赖顺序明确。

## Coding

扩展条件：数据库映射、数据副作用、配置生效链路、边界分支或相关测试缺失。

停止条件：精确修改入口、调用方、Mapper/SQL/字段、配置绑定与生效条件、验证命令齐全。

## Testing

扩展条件：Fixture、数据库约束、测试 Profile、环境差异、外部依赖隔离或回归范围不清。

停止条件：相关正常、异常、边界、权限、幂等或并发场景有证据，数据准备、测试配置和执行命令明确。

## Review

必须读取并对照：MR/提交范围、当前代码 Diff、数据库变更文档、配置变更文档、完整变更包及验证记录。检查字段/索引/约束、配置快照和生效条件是否与变更摘要一致。

扩展条件：任一来源缺失、互相冲突，或 Diff 影响公共契约、数据库、配置、异步链路或未覆盖调用方。

停止条件：MR、数据库文档、配置文档、变更包和 KnowledgeBase 对任务相关变化均有一致性结论，测试充分性与回归风险明确。

## Debug

必须读取并对照：目标环境配置快照、配置键绑定与生效条件、数据源路由、执行 SQL、字段值/状态、相关测试和最近变更包。

扩展条件：症状可由多个入口、环境覆盖、开关、数据源、SQL、字段状态、并发或中间件路径解释。

停止条件：事实与假设分离，配置生效链和数据访问链已定位，候选根因按四类证据排序，每个高优先级根因有安全验证入口。
