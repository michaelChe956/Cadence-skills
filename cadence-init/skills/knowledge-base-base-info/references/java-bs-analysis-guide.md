## 仓库与模块信号

| 信号 | 可能含义 | 需要继续确认 |
|------|----------|--------------|
| 根 `pom.xml` 含 `<modules>` | Maven 多模块 | 子模块是否独立服务 |
| 多个启动类 | 多服务或测试入口 | 是否在生产构建中启用 |
| `settings.gradle` | Gradle 多项目 | include 与目录映射 |
| 多个 `package.json` | 多前端或 Monorepo | workspace 和部署单元 |
| Gateway 配置 | 可能存在外部路由 | 实际 Profile 与部署配置 |

## Java 分析重点

### 启动与装配

- `@SpringBootApplication` 的扫描范围
- `@EnableConfigurationProperties`
- `@Conditional*` 条件
- AutoConfiguration 和 SPI
- Profile、Feature Flag 和外部配置

### 数据访问

- JPA Entity、Repository 和命名查询
- MyBatis Mapper、XML 和动态 SQL
- MyBatis-Plus Wrapper 和逻辑删除
- JDBC Template 和手写 SQL
- Flyway、Liquibase 和自定义迁移

### 隐式调用

- AOP 切面
- 事件监听器
- 反射、SPI、动态代理
- Spring Bean 名称查找
- 注解驱动的消息、缓存、事务和调度

## 前端分析重点

- 锁文件用于确认实际依赖版本
- 构建配置用于确认别名、代理和环境变量
- 路由与菜单可能分别来自代码和后端
- 请求封装可能统一注入 Token、租户和错误处理
- 状态管理可能控制权限、Feature Flag 和动态路由

## DDL 分析重点

按数据库方言识别：

- 标识符大小写与引用方式
- 自增、序列或触发器生成 ID
- 索引类型、分区和表空间
- 字段注释与表注释
- 视图、函数、过程和触发器依赖

跨文件 DDL 必须先确定执行顺序和所属 Schema。分库分表需要区分逻辑表与物理表，不重复把每个物理分片当成独立业务实体。

## 字段级数据模型生成规则

### 固定输出层级

`data-models/` 始终生成，固定分为三层：

1. `data-models/README.md`：数据模型总索引，覆盖全部数据库、Schema 和逻辑表。
2. `data-models/<数据库或 Schema 稳定 ID>/README.md`：当前数据库或 Schema 的表清单与关系导航，不复制完整字段清单。
3. `data-models/<数据库或 Schema 稳定 ID>/<逻辑表稳定 ID>.md`：每张逻辑表的字段级文档。

禁止用单个 `data-model-overview.md` 替代上述输出。一张逻辑表只生成一个文档；`t_order_00` 至 `t_order_15` 等物理分片只写入逻辑表文档的分库分表章节。

### 逻辑表识别

- 优先使用 DDL 或迁移中的表定义确认物理名称，以配置中的路由规则识别逻辑表与物理分片范围。
- Entity 的 `@Table`、MyBatis Mapper、SQL 的 `FROM`、`JOIN`、`INSERT INTO`、`UPDATE` 和 `DELETE FROM` 可以提供代码映射证据。
- 多个物理表具有相同结构并符合明确分片规则时，合并为一个逻辑表；不能仅凭名称相似自行归并。
- 为逻辑表分配稳定 ID，例如 `TABLE-order`；数据库、Schema、服务、API、页面和配置组也使用稳定 ID 关联。

### 字段清单

每张逻辑表必须逐字段记录：字段、类型、可空、默认值、主键、含义、代码映射、证据状态和证据位置。字段清单的证据状态只允许：

- `DDL 已确认`
- `迁移已确认`
- `代码可推导`
- `用户提供`
- `来源冲突`
- `待确认`

证据状态描述当前字段行最可靠的结构来源。某个属性缺少证据时，该属性单元格仍写 `待确认`，不能因字段名可由代码推导而补造类型、可空性、默认值或主键状态。证据位置必须定位到文件、对象、SQL statement 或用户资料条目。

### 索引、约束与关系

- 只有 DDL、迁移或明确人工资料直接定义的实际索引、主外键、唯一约束和检查约束，才能按对应证据状态记录为数据库结构。
- Entity 注解、MyBatis 映射或 SQL 用法只能描述代码侧意图或候选关系；没有 DDL 时，实际数据库索引、默认值和约束写 `待确认`。
- 同名字段不能单独证明外键关系。显式外键可标 `DDL 已确认` 或 `迁移已确认`；明确 ORM 关联、SQL `JOIN` 语义或用户资料只能按其来源记录，并说明未确认数据库外键。
- 记录复合索引或复合约束时保留字段顺序；来源未给出顺序时不得补全。

### Mapper、SQL 与读写服务

- 记录 Entity 字段与数据库字段映射、Mapper 接口、Mapper XML statement、Repository 查询、JDBC Template 和手写 SQL。
- 按 `SELECT`、`INSERT`、`UPDATE`、`DELETE` 区分操作，并关联调用它们的服务稳定 ID 与方法位置。
- 能追踪到 API 或页面时，分别关联 API 稳定 ID 和页面稳定 ID；无法追踪时写 `待确认`，不得仅凭命名猜测。
- 动态 SQL 需要记录条件分支可能引用的字段，并说明静态分析无法保证运行时覆盖完整。

## 证据合并与降级

### 离线证据边界

数据库事实只能来自 Manifest 授权的只读 DDL、迁移、代码、配置和人工资料。不得建立 JDBC、数据库客户端或其他数据库连接，不得查询系统表、`information_schema`、Schema Catalog 或数据库结构，也不得访问在线元数据服务补充或验证证据。授权资料没有覆盖的结构属性必须标记 `待确认`，不能通过连接运行中数据库补证。

### 来源处理顺序

不要用固定优先级覆盖冲突。先分别记录 DDL、迁移、Entity、Mapper、SQL、配置和人工资料，再按属性合并：

1. 来源一致时保留全部证据位置，并使用最直接的证据状态。
2. 名称、类型、可空性、默认值、主键或约束不一致时标 `来源冲突`，列出各来源原值及影响。
3. 迁移片段只有在所属 Schema、执行顺序和适用版本可确认时标 `迁移已确认`；否则说明限制并标 `待确认` 或 `来源冲突`。
4. 用户资料明确给出的事实标 `用户提供`，不自动升级为 DDL 或迁移事实。

### 无 DDL 场景

没有 DDL 时仍生成总索引、Schema 索引和每张逻辑表的字段级文档：

- Entity、Mapper 和 SQL 明确出现的表名、字段名和映射关系可标 `代码可推导`。
- Java 类型只能记录为代码类型；数据库类型若无迁移或人工资料支持则写 `待确认`。
- 实际可空性、默认值、主键、外键、唯一约束、检查约束和索引全部保持 `待确认`。
- 在表文档的“证据与来源冲突”中声明完整性限制，例如动态 SQL 分支、运行时表名、未纳入的外部 Mapper 或缺失迁移顺序。
- 无任何来源支持的字段或属性不得补造；未覆盖对象进入 Schema 索引和 `open-questions.md`。

## 配置快照与服务配置文档

### 一级证据与不可变边界

配置与代码、数据模型同为一级证据，必须生成独立配置领域文档，不能把配置键清单塞入基础信息或数据模型摘要。分析只接受 Manifest 4.0 的 `scope.configurations` 与 `evidence.configuration_snapshots`：

1. 外部原始快照全程只读，不复制进 KnowledgeBase，不写入、重命名、删除或格式化源文件。
2. 不连接配置中心、远程环境或在线元数据源补取配置。
3. 不跟随符号链接、挂载点或文件内引用越过授权快照目录；越界项登记为 `待确认`。
4. 分析开始和结束时按 Manifest 4.0 输入契约计算最终快照指纹。只有前后指纹一致时才能写入配置结论；不一致时立即停止。
5. Manifest 的 `evidence.configuration_snapshots` 只保存最终快照指纹和来源元数据，不保存单文件内容哈希或敏感值哈希。

### 文件分类

| 文件或信号 | 归属 | 处理规则 |
|------------|------|----------|
| `.properties`、`.yml`、`.yaml` | 配置 | 识别扁平键、层级键、环境和 Profile，不复制敏感值 |
| Spring 等运行时 XML | 配置 | 记录配置键、Bean 引用、加载来源与生效条件 |
| Nginx `.conf` 与缓存文件 | 配置 | 记录用途、适用服务和加载链路；内部域名、IP、URL 脱敏 |
| Mapper XML | 数据模型 | 转交字段级数据模型分析，配置文档只建立关系，不复制 SQL 或字段清单 |
| 日志 XML、日志 Properties 或 YAML | 可观测性 | 归入日志与可观测性，服务配置文档只记录导航和装配关系 |
| 部署、发布、启动脚本 | 加载链路证据 | 只读分析配置来源、加载顺序和部署方式，禁止执行 |
| `.idea`、`.gitkeep`、空文件 | 排除 | 默认不纳入配置基线 |
| 明确历史备份 | 排除 | 如日期后缀、`.bak`、`.old` 且可明确为历史副本；不确定时标 `待确认` |

无扩展名文件、JSON、INI 或其他 XML 不能只凭扩展名归类，必须结合文件名、结构和加载引用判断。生成代码、测试、Mock 和示例配置必须单独标记，不能作为生产配置的唯一证据。

### 相同内容文件与哈希安全

- 先按授权范围、服务、环境和 Profile 建立候选集合，再比较内容；相同 basename 不代表相同配置。
- 内容完全相同的文件合并分析一次，并记录全部适用服务、环境、Profile 和来源位置。
- 同名但内容不同、加载顺序不同或适用范围不同的文件分别保留，必要时标记 `来源冲突`。
- 重复文件哈希只允许保存在当前分析进程的临时状态，用完即丢弃；不得写入配置索引、服务文档、证据索引、Manifest 或其他 KnowledgeBase 文件。
- 不得对密码、Token、AccessKey、Secret、密钥、私钥、完整连接串或内部端点值生成并保存普通哈希、确定性摘要或其他可关联衍生物。

### 敏感配置处理

键名、路径、注释或上下文出现密码、口令、Token、AccessKey、Secret、Credential、密钥、私钥、连接串、域名、Host、IP、URL、Endpoint 等信号时，按敏感配置处理。加密文本、环境变量引用和占位符不自动视为安全值；文档只记录配置键、用途和值类型，值统一写为 `<redacted>`。无法确定是否敏感时同样脱敏并登记 `待确认`。

### 固定输出

配置目录固定分为两层：

1. `configurations/README.md`：记录当前配置基线、来源与加载顺序、环境与 Profile、服务导航、配置组影响、敏感策略、快照差异和待确认项。
2. `configurations/<服务稳定 ID>.md`：为 `scope.configurations` 范围内每个服务生成一个文档，记录配置来源、键清单、绑定、生效条件、数据源、分片、中间件、敏感配置和变更记录。

配置状态为 `不适用` 时仍生成总索引并记录原因，不读取快照。状态为 `全量` 或 `指定` 时，即使某服务没有发现配置键，也生成服务文档并把关键项标为 `缺失` 或 `待确认`。配置键状态只允许：

- `存在`
- `新增`
- `删除`
- `修改`
- `缺失`
- `来源冲突`
- `待确认`

## 配置与代码、数据模型及中间件的关系

配置值的存在不等于生效。结合以下证据判断：

1. Profile 或配置中心加载范围
2. Bean 条件装配
3. 调用、Listener、Producer 或客户端创建
4. 网关、部署或运行资料

配置键与 `@ConfigurationProperties`、`@Value`、Bean 工厂、条件注解或前端环境变量绑定时，记录配置键、代码位置和生效条件。只发现键或绑定声明而未发现加载链路时标 `待确认`。

Mapper XML 始终归数据模型。服务配置文档可以关联数据源、Schema、逻辑表稳定 ID 和分片配置，但不得复制字段级清单，也不得把路由配置升级为实际数据库结构。

中间件配置需要同时检查依赖、装配、客户端创建、Producer/Consumer/Listener 或实际调用。只有配置键不能证明中间件已启用；来源不一致时保留各环境证据并标 `来源冲突`。

## 横切关注点

重点寻找：

- Spring Security Chain、权限注解和自定义鉴权
- `@Transactional`、事务管理器和事件边界
- `@Cacheable`、RedisTemplate 和本地缓存
- Resilience4j、Sentinel、Hystrix 或自定义重试
- 全局异常处理和错误码枚举
- 日志 Trace ID、Micrometer、OpenTelemetry 或 SkyWalking

## 常见误判

- 依赖存在即认定实际使用
- Controller 存在即认定外部暴露
- 同名字段即认定外键关系
- 开发配置即认定生产配置
- 把原始配置快照复制进 KnowledgeBase
- 用相同 basename 直接判定文件内容相同
- 把运行时重复文件哈希或敏感值哈希写入 KnowledgeBase
- 把 Mapper XML 归入配置文档并复制 SQL
- 执行部署、发布或启动脚本来验证加载顺序
- 把日志配置当成普通业务配置而不归入可观测性
- 记录完整连接串、内部域名、IP 或 URL
- 测试启动类即认定生产服务
- Entity 结构即认定数据库实际结构
- 代码查询字段即认定真实索引、默认值或数据库约束
- 同名字段即认定数据库外键
- 为每个物理分片重复生成逻辑表文档
- 用数据模型摘要代替每张逻辑表的字段清单
- README 中的旧版本说明即认定当前版本
