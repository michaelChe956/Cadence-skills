
### 测试流程（一个容器内）
1. `create_test_container(agent)` — 启动容器+装 CLI+复制认证+运行 install.sh
2. `create_test_project(c)` — 创建 users 模块测试项目
3. `run_stage1(c, agent)` — 三命令安装（pre-check→mcp→rule-config，prx 暂跳）
4. `run_probe(c, agent, prompt)` — 探针会话
5. `_score_probe_text()` — 文本级评分
6. `c.destroy()` — 容器销毁

### 四端 CLI 命令
| 端 | 命令 |
|---|---|
| claude | `claude -p "{prompt}" --dangerously-skip-permissions` |
| codex | `codex exec --json -s danger-full-access "{prompt}"` |
| pi | `pi -p "{prompt}"` |
| kimi | `kimi -p "{prompt}"` |

### 使用规则

1. 检索代码 → scout[luna]（深度）或 glm5.3-f-scout[flash]（快速）
2. 做决策 → oracle[k3:max]，context:"fresh" + 自给足文件路径（k3 走 Anthropic 协议但非 Anthropic 模型，fork 可能没问题但保守用 fresh）
3. 实现 → task[glm-5.3] 默认；提速用 max-task[astra:minimal]；稳定用 glm53-task；省钱批量用 ds-task[deepseek-v4-flash]
4. 评审 → k3-reviewer[k3:high]（spec 合规）；reviewer[glm-5.3:high]（快速）
5. 调研 → researcher[bingqi/glm-5.3:max]
6. 尽量并行，注意共享文件冲突（tests 目录/skill-clause-map 并行必撞）
7. subagent 环境出问题只报告用户，禁止自行修复
8. 504 先核对文件是否已改再决定重派（不等于失败）
9. reviewer 必须全量测试计数逐模块对账贴原文
10. 续任务全新自含派工；大任务 3h 上限；worker 禁抹除性 git
11. 排查问题优先 max-task[astra]（注意 astra 有 504 史，连续两次 504 换 k3-reviewer 或 oracle 顶上）

### 模型使用规则

- 主会话：glm-5.3（default 角色）
- 深度推理：k3:high 或 k3:max（slow/plan 角色）
- 快速任务：glm-5.3-flash（smol/tiny 角色）
- 图像：glm-5.3-flash（vision 角色，支持看图）
- 省钱批量：deepseek-v4-flash（$0.14/M，其他模型的 1/10）
- 长输出：deepseek-v4-pro（384K max output）
- 避免：claude-opus-5（余额仅 $0.16）、anthropic-kiro-person（token 失效）
