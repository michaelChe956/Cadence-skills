# KnowledgeBase 技能套件技术方案

## 1. 目标

在 `cadence-init/skills/` 下新增一套扁平化技能，用于分析存量 Java 后端与 Vue/React 前端项目，并在目标项目的 `cadence/knowledgeBase/` 中生成面向 Coding Agent 的项目知识库。

技能同时兼容 Claude Code 和 Codex，不依赖某个运行时独有的命令或 MCP。存在代码图、AST 大纲等结构化工具时优先使用；工具不可用时必须降级到文件检索和定向源码阅读。

## 2. 适用范围

### 2.1 后端

- Java 单体、多模块和微服务项目
- Spring Boot、Spring Cloud、Dubbo 等常见架构
- Maven、Gradle 构建体系
- REST、Feign、Dubbo、消息、缓存、文件交换、定时任务等能力

### 2.2 前端

- Vue 2、Vue 3
- React
- Vue Router、React Router 及框架封装路由
- Axios、Fetch 及项目自定义请求封装
- Vuex、Pinia、Redux、Zustand 等状态管理方式

### 2.3 不在首版范围

- 自动修改业务代码
- 自动修复项目缺陷
- 根据生产数据库建立在线连接
- 将配置文件中的密码、Token、密钥或完整连接串写入知识库
- 强制要求特定 MCP、IDE 或商业工具

## 3. 技能结构

```text
cadence-init/skills/
├── knowledge-base-bootstrap/
├── knowledge-base-base-info/
├── knowledge-base-api/
├── knowledge-base-pages/
├── knowledge-base-overview/
└── knowledge-base-update/
```

每个技能目录至少包含：

```text
<skill-name>/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── references/
└── assets/
```

只创建确实需要的 `references/` 与 `assets/` 文件，不创建技能级 README、安装指南或变更日志。

## 4. 技能职责

### 4.1 knowledge-base-bootstrap

作为用户首选入口，负责：

1. 读取目标项目的 `AGENTS.md`、`CLAUDE.md` 与项目规则。
2. 识别仓库形态、技术栈、模块和服务边界。
3. 引导用户提供 DDL、配置文件、中间件清单、API 文档、页面路由和领域术语。
4. 对用户输入执行完整性检查和敏感信息提示。
5. 创建 `cadence/knowledgeBase/` 目录和知识库清单。
6. 按依赖顺序调用其他领域技能。
7. 执行跨文档一致性、链接、证据和待确认项检查。

推荐执行顺序：

```text
base-info → api → pages → overview
```

缺失输入时不得伪造。用户确认资料暂不可得后，可以进入“有限证据模式”，根据代码生成可确认部分，并将缺失项写入待确认清单。

### 4.2 knowledge-base-base-info

负责生成基础信息，包括：

- 项目与仓库形态
- 后端、前端技术栈和版本
- 模块、服务、构建与启动方式
- DDL、数据库、Schema、表、主外键和分库分表规则
- 配置文件、环境差异和配置来源
- 中间件版本、用途、生产者、消费者和关键配置
- 数据源、中间件与代码模块之间的关系
- 部署形态和外部依赖
- 已知风险、未知信息和待人工确认项

### 4.3 knowledge-base-api

负责盘点系统提供或使用的能力，并明确区分：

- 对外公开 REST API
- 对内 REST API
- 服务间 REST/RPC 调用
- Dubbo 等 RPC 接口
- Kafka、RabbitMQ、RocketMQ 等消息接口
- Redis Pub/Sub、Stream 或队列式用法
- FTP、SFTP、对象存储和批量文件交换
- 定时任务、批处理和异步作业

每项能力至少记录入口、调用方、实现位置、鉴权、请求或消息模型、响应或副作用、依赖数据、错误语义和证据来源。

### 4.4 knowledge-base-pages

负责前端页面能力，包括：

- 路由路径、路由名称和页面组件
- 动态路由、嵌套路由和重定向
- 登录态、菜单、角色、权限与路由守卫
- 页面用途、主要操作和状态来源
- 页面调用的 API、涉及的数据实体和后端模块
- 公共组件、布局、状态管理和请求封装
- 代码中存在但不可达的页面，以及有路由但缺少实现的异常项

### 4.5 knowledge-base-overview

负责生成面向 Coding Agent 的入口和导航，包括：

- 项目一句话说明
- 系统边界和核心业务流程
- 模块、服务、页面、API、数据模型的导航
- 行业术语、缩写、特殊用语和同义词
- 常见修改场景对应的必读文档
- 未决问题和高风险区域

该技能还负责安全更新目标项目的 `CLAUDE.md` 与 `AGENTS.md`：

1. 文件不存在时创建最小入口文件。
2. 文件存在时保留原内容，只更新带稳定标记的 KnowledgeBase 管理区块。
3. 在 `cadence/project-rules/knowledge-base-usage.md` 中保存详细的项目级使用规则。
4. 禁止覆盖目标项目已有规则或将用户规则写入框架内置规则目录。

### 4.6 knowledge-base-update

负责迭代后的增量维护，包括：

- 获取用户提供的增量 DDL、配置、中间件和领域资料
- 读取知识库基线提交与当前 Git 状态
- 分析基线提交到当前提交的代码差异
- 建立变更文件到模块、API、页面、数据表和中间件的影响映射
- 只更新受影响章节，同时删除已经失效的自动生成内容
- 保留人工备注，冲突时生成待确认项而非静默覆盖
- 更新知识库清单、生成时间、基线提交和变更历史

## 5. 输入契约

### 5.1 用户输入目录

总控技能引导用户将资料放入目标项目：

```text
cadence/knowledgeBase/inputs/
├── ddl/
├── config/
├── api/
├── routes/
├── middleware.md
├── glossary.md
└── notes.md
```

原始配置文件可以保留在原位置，仅在 `inputs/config/` 放置副本或路径清单。技能分析前必须提醒用户移除或遮蔽密码、密钥、Token、证书私钥和敏感地址。

### 5.2 输入状态

每类输入标记为以下状态之一：

| 状态 | 含义 |
|------|------|
| 已提供 | 用户提供了可分析资料 |
| 代码可推导 | 未提供独立文档，但代码中存在较强证据 |
| 用户确认缺失 | 用户明确表示当前无法提供 |
| 待确认 | 尚未得到用户答复或证据不足 |

## 6. 输出契约

目标项目统一生成：

```text
cadence/knowledgeBase/
├── README.md
├── 00-project-overview.md
├── 01-base-information.md
├── 02-api-capabilities.md
├── 03-page-capabilities.md
├── 04-domain-glossary.md
├── 05-change-history.md
├── manifest.yaml
├── inputs/
└── evidence/
```

### 6.1 manifest.yaml

知识库清单至少记录：

- 知识库版本
- 生成时间
- 生成模式
- Git 基线提交
- 项目模块与服务列表
- 输入资料状态
- 各文档路径、负责人技能和最近更新时间
- 待确认项数量

### 6.2 证据标签

重要结论必须使用以下标签之一：

| 标签 | 使用条件 |
|------|----------|
| `[代码事实]` | 可由明确源码位置证明 |
| `[DDL事实]` | 可由用户提供的 DDL 证明 |
| `[配置事实]` | 可由配置项证明 |
| `[用户提供]` | 来源为用户文档或口头说明 |
| `[合理推断]` | 多个间接证据支持，但缺少直接定义 |
| `[待人工确认]` | 证据冲突、信息缺失或无法确定 |

重要事实同时记录可定位的证据路径；能定位到符号时记录类、方法、路由、配置键或表名，避免只写宽泛目录。

### 6.3 自动内容与人工内容

增量更新需要区分：

- 技能自动生成内容
- 用户人工维护内容
- 待确认内容

模板通过稳定章节和管理标记实现局部更新。技能不得删除管理标记之外的用户内容。

## 7. 分析策略

### 7.1 代码阅读

1. 先识别仓库、模块和服务边界。
2. 大范围调用关系优先使用可用的代码图工具。
3. 类、方法、路由和配置绑定优先使用 AST 或结构化大纲。
4. 工具不可用时，使用文本检索定位候选，再定向读取目标文件。
5. 避免无边界地读取整个仓库或生成完整源码副本。

### 7.2 Java 识别重点

- `pom.xml`、`build.gradle`、父子模块关系
- Spring Boot 启动类和自动配置
- Controller、Feign Client、Dubbo Provider/Consumer
- Service、Repository、Mapper、Entity、DTO
- MyBatis XML、JPA 映射和数据库迁移文件
- Spring Security、网关、过滤器和拦截器
- 消息监听器、生产者、调度任务和批处理
- Nacos、Apollo、Consul、Spring Cloud Config 等外部配置来源

### 7.3 Vue/React 识别重点

- 包管理器、构建工具和框架版本
- 路由定义、动态路由和权限守卫
- 页面组件与布局
- 请求客户端与 API 模块
- 状态管理和权限状态
- 环境变量、代理和后端基础地址

## 8. 冲突与异常处理

| 场景 | 处理方式 |
|------|----------|
| API 文档与代码不一致 | 同时记录两者，以代码现状为“实现事实”，将文档差异标为待确认 |
| DDL 与 ORM 映射不一致 | 保留两种定义并标记影响范围，不自行选择正确版本 |
| 配置包含敏感值 | 只记录配置键、用途和值类型，使用 `<redacted>` 替换原值 |
| 无 Git 仓库 | 允许首次全量生成；增量更新依赖用户变更清单和文件差异 |
| 多仓库项目 | 为每个仓库记录独立基线，并在概览中建立跨仓导航 |
| 项目规模过大 | 按服务或模块分批生成，完成一个边界后再合并索引 |
| 工具不可用 | 使用规定的降级策略，不因工具缺失中止整个流程 |

## 9. 双端兼容约束

- `SKILL.md` frontmatter 只使用 `name` 和 `description`。
- 技能名只使用小写字母、数字和连字符，目录名与 `name` 完全一致。
- 正文不使用仅 Claude Code 或仅 Codex 支持的强制语法。
- 不硬编码 MCP 工具名；描述所需能力和降级路径。
- 为 Codex 提供 `agents/openai.yaml`，Claude Code 可忽略该目录。
- 不依赖子代理才能完成核心流程；存在并发能力时可以按独立模块并行分析。
- 所有最终交互和知识库文档默认使用中文，源码标识、配置键和协议名称保留原文。

## 10. 验收标准

### 10.1 结构

- 六个技能均位于 `cadence-init/skills/` 的直接子目录。
- 每个技能的目录名与 frontmatter `name` 一致。
- 每个技能包含有效的 `SKILL.md` 和 `agents/openai.yaml`。
- 不包含占位符、无用途的脚本或技能级 README。

### 10.2 行为

- 总控技能能够引导用户补充输入并选择完整模式或有限证据模式。
- 基础信息、API、页面和概览技能的边界清晰，不重复生成整套知识库。
- API 文档明确区分对外、对内、服务间和非 HTTP 能力。
- 页面文档能建立路由、页面、API、后端模块和数据实体的关联。
- 增量技能能根据基线和变更范围更新受影响内容，并保护人工内容。
- 配置分析不会泄露敏感值。
- 生成结论包含证据标签和可定位来源。
- 工具缺失时存在可执行的降级路径。

### 10.3 验证

- 使用技能结构验证工具逐个验证六个技能。
- 检查所有相对引用和模板文件是否存在。
- 检查 frontmatter、技能名和 `openai.yaml` 的一致性。
- 使用代表性场景分别验证总控、基础信息、API、页面、概览和增量更新行为。
- 最后检查仓库工作区差异，确保没有修改 `.claude/rules/` 等框架内置规则。
