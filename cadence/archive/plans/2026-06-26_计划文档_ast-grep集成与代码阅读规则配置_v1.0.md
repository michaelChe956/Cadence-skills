### 2. rule-config skill 增加 ast-grep outline 代码阅读规则

#### 2.1 新增规则模板

**文件**：`cadence-init/references/rules/code-reading.md`

**内容来源**：参考 `cadence-aria/.worktrees/feat-b-0616/.claude/rules/code-reading.md`，结构与核心要点如下：

- **核心原则**：结构化优先，避免盲读整片代码。
- **必须优先使用 `ast-grep outline`**：在阅读、检索、理解代码时，先获取文件或目录的结构化大纲（函数、类、结构体、导入导出、成员及其源码区间），再基于大纲决定精读范围。
- **基于大纲定向精读**：拿到大纲后，仅对真正需要的符号/区间做进一步阅读；先用 `--match` / `--view` 展开目标符号的签名或成员，再决定是否需要读取完整实现。
- **检索代码时同样适用**：查找符号定义、模块导出、依赖导入等结构化问题时，优先用 `ast-grep outline` 而非 `grep` 或整文件读取。
- **命令示例**：
  - `ast-grep outline src/parser.ts`
  - `ast-grep outline src`
  - `ast-grep outline src/parser.ts --items imports`
  - `ast-grep outline src/parser.ts --match Parser --type class --view expanded`
  - `ast-grep outline src --items imports --match ast-grep-core --view signatures`
- **常用参数表**：`--items`、`--match`、`--type`、`--view`。
- **适用场景判断**：
  - ✅ 鼓励：理解陌生文件结构、定位符号定义、梳理模块导出/导入关系、在大型仓库中建立结构地图。
  - ⚠️ 需说明：文件极小或已明确需要完整实现时可直接读取，但应说明跳过 outline 的原因。
  - ❌ 避免：不先看大纲直接整文件读取大型源码文件；避免用 `grep` 替代 outline 做结构化定位。
- **参考资源**：`ast-grep outline --help`、官方设计说明。
