# Cadence 项目知识文档

## 文档定位与变更边界

本文是 Cadence 仓库面向开发者和维护者的单一知识入口，记录当前目录职责、网络安装脚本、三层 skill 级软链、四类 Agent 消费路径、迁移和发布门禁。

本次变更范围只包括：

- 仓库根目录 `install.sh` 的网络安装、更新、链接同步和卸载机制。
- `~/.agents/Cadence-skills` 用户安装仓库及其共享/客户端链接层。
- 根 `README.md`、`readmes/` 七份用户文档和本文档。

本次变更不改动：

- `cadence-init` 的 14 个 Skill 行为、输入输出和运行时边界。
- `pre-check` 的运行时工具安装逻辑。
- 既有 OpenSpec specs 和本次变更之外的项目契约。

本文描述实现事实和维护边界，不产生新的安装接口。所有公开安装命令以 `install.sh` 实际接口和根 README 为准。

## 网络安装脚本架构

### 固定数据流

```text
MIRRORS
  → 临时 Git clone 或已有 Git 仓库
  → ~/.agents/Cadence-skills/cadence-init/skills/<skill>/SKILL.md
  → ~/.agents/skills/<skill>
  → ~/.claude/skills/<skill>
  → ~/.codex/skills/skills/<skill>
```

共享层 `~/.agents/skills/<skill>` 指向安装仓库中的 Skill 源；Claude Code 和 Codex 兼容层再指向共享层。链接粒度是单个 Skill 目录，不链接整个 skills 根目录，以减少不同 Agent 对根目录软链处理差异的影响。

### 函数接口与责任

| 函数 | 责任 |
| --- | --- |
| `clone_with_rotation()` | 按 `MIRRORS` 顺序尝试三个镜像，对目标仓库执行临时 clone；三个镜像全部失败即报错，不直连 GitHub |
| `update_repo()` | 解析 `origin` 跟踪分支，执行 `fetch --all`、`pull --ff-only`，失败时轮换镜像并重试；拒绝强制覆盖本地历史 |
| `ensure_repo()` | 区分目标不存在、有效 Git 仓库和非 Git 目录；非 Git 目录只提示用户先手动处理，不自动删除 |
| `is_managed_link()` | readlink 符号级所有权证明：共享层条目目标精确等于 `~/.agents/Cadence-skills/cadence-init/skills/<name>`；Claude/Codex 层条目目标精确等于 `~/.agents/skills/<name>` 且该共享层条目本身通过所有权证明；install 与 `--uninstall` 共用同一谓词 |
| `run_dry_run()` | 组合安装或卸载预览参数，生成并稳定排序动作计划；预览不联网、不落盘 |
| `plan_repository()` / `plan_sync_links()` | 共同生成安装预览：分别计算仓库保留/clone 预览与三层 Skill 链接创建、替换、保留、冲突告警和孤儿清理计划 |
| `plan_uninstall()` | 按同一所有权谓词生成受管链接卸载及可选 `--delete-repo` 仓库删除计划，不直接执行删除 |
| `plan_link()` | 计算单个链接的创建、保持、替换或告警跳过动作 |
| `plan_remove_link()` | 计算单个链接的受管删除或告警跳过动作，保护普通文件、目录和非受管软链 |
| `sync_one_link()` | 生成动作计划；替换动作由 `execute_action` 的 `REPLACE` 分支以临时链接+`mv -T` 原子执行 |
| `execute_plan()` | 按动作计划顺序调用执行器，统一执行安装同步或卸载动作 |
| `execute_action()` | 执行单个 `ENSURE-DIR`、`CREATE`、`REPLACE`、`REMOVE`、`REMOVE-REPO` 等动作，并在执行前复核所有权 |
| `sync_links()` | 扫描 14 个 `SKILL.md` 对应的 Skill 目录，建立三层链接并清理受管孤儿链接 |
| `detect_residue()` | 只检测并提示历史安装残留，不自动改动历史目录或 JSON 登记 |
| `uninstall()` | 仅移除受管 Skill 链接；只有显式 `--delete-repo` 才删除安装仓库 |
| `print_visibility()` | 输出 Claude Code、pi、Codex、Kimi Code 的可见路径及同步结果 |
| `main()` | 解析无参数安装、`--help`、`--dry-run`、`--uninstall`、`--uninstall --delete-repo` 及对应预览组合，编排上述流程和错误返回 |

函数名是当前脚本的实现接口文档，不应在其他文档中另造函数别名或以模糊的“同步逻辑”替代。实现维护时保持函数职责单一，破坏性操作必须先经过精确受管判定。

### 失败语义与安全边界

- 三个镜像按固定顺序失败后终止，禁止添加直连兜底或离线路径。
- Git 更新必须快进；远端强推、分支无法解析或 fetch/pull 失败时报告恢复建议，不重置用户提交。
- 目标路径是非 Git 目录时只告警并终止安装，不自动删除目录。
- Skill 目标遇到用户普通文件、目录或非受管软链时保留原对象，并报告冲突。
- 孤儿清理只针对能由 `is_managed_link()` 精确判定的链接。
- 原子替换只作用于受管目标；不跟随链接删除用户文件。
- 旧安装残留只提示，由用户人工核对和清理。
- 卸载默认保留 Git 仓库；仓库删除必须由用户明确传入 `--delete-repo`。

## 四类 Agent 消费路径

| Agent | 读取路径 | 本安装提供的链接 |
| --- | --- | --- |
| Claude Code | `~/.claude/skills/` | skill 级链接到 `~/.agents/skills/<skill>` |
| pi | `~/.agents/skills/` | 共享层直接指向仓库源 |
| Codex | `~/.agents/skills/`；兼容 `~/.codex/skills/skills/` | 共享层与 Codex 兼容层 |
| Kimi Code | `~/.agents/skills/` | 共享层直接指向仓库源 |

研究基线显示 Claude Code、pi 和 Codex 支持 skill 级软链；Kimi Code 对该行为缺少充分的官方说明，发布门禁必须加入真实可见性验证。无论客户端如何发现，Skill 源和安装链接均由同一个 `~/.agents/Cadence-skills` 仓库提供。

## 新旧安装机制对照

| 维度 | 历史机制 | 当前机制 |
| --- | --- | --- |
| 获取源 | 本地复制插件内容 | 固定镜像顺序 clone 到 `~/.agents/Cadence-skills` |
| Skill 源 | 旧插件目录副本 | `cadence-init/skills/<skill>/SKILL.md` |
| Claude Code 入口 | 历史插件目录 | `~/.claude/skills/<skill>` |
| 共享消费 | 没有统一共享层 | `~/.agents/skills/<skill>` |
| Codex 兼容 | 依赖旧插件发现方式 | `~/.codex/skills/skills/<skill>` |
| 注册方式 | 历史上写入旧插件登记文件 | 不注册插件市场，依靠三层 skill 级链接 |
| 更新方式 | 复制本地内容 | 重新运行 `install.sh`，更新仓库并重同步链接 |

历史实现曾把内容复制到 `~/.claude/plugins/marketplaces/cadence-skills-local`，并使用 `~/.claude/plugins/known_marketplaces.json` 保存登记信息。这些路径只用于识别历史残留，不是当前安装目录、更新入口或消费路径。当前机制不注册插件市场。

## 迁移与卸载

### 迁移

先运行当前安装脚本，确认三个消费层可见，再按需手动处理历史残留：

```bash
bash ~/.agents/Cadence-skills/install.sh
rm -rf -- ~/.claude/plugins/marketplaces/cadence-skills-local
```

删除旧目录前应确认其中没有其他用户内容。对于 `~/.claude/plugins/known_marketplaces.json`，先备份，再用 `jq` 或其他 JSON 工具人工复核，删除其中与 `cadence-skills-local` 对应的键；脚本只检测并提示，绝不自动改动该文件。

迁移不得执行历史注册流程，也不得把旧目录重新当作当前安装源。若 `~/.agents/Cadence-skills` 是非 Git 目录，先由用户手动移走或删除，再重新运行安装。

### 卸载

只卸载链接：

```bash
bash ~/.agents/Cadence-skills/install.sh --uninstall
```

卸载链接并显式删除安装仓库：

```bash
bash ~/.agents/Cadence-skills/install.sh --uninstall --delete-repo
```

`uninstall()` 只删除精确识别为受管的三层 Skill 链接；普通文件、目录、非受管软链和其他 Agent 的普通 Skills 均保留。默认卸载保留仓库，以便恢复或再次同步；删除仓库是明确的破坏性选项。

## 测试与发布门禁

发布 `install.sh` 或同步文档前，至少执行以下门禁：

1. **ShellCheck**：对 `install.sh` 和 `tests/test-install.sh` 执行 `shellcheck --shell=bash --severity=warning`。
2. **隔离 HOME 自动测试**：使用 `HOME=$(mktemp -d)` 运行 `bash tests/test-install.sh`；测试不得触碰真实 HOME。
3. **14×3 链接解析矩阵**：从仓库 `cadence-init/skills/*/SKILL.md` 产生唯一 14 个 Skill 集合，逐项检查共享层、Claude Code 层和 Codex 兼容层共 14×3 条链接及最终 `SKILL.md` 可读性；同时保留第三方形状链、普通目录和 dangling 链 fixture，确认它们不被误删或覆盖。
4. **真机重验（SHOULD，一次性留档）**：按唯一顺序执行“快照三层链清单 → `--dry-run` 人工核对 → 实装 → 对已存在条目 diff 为空（全新首装场景允许且仅允许新增链接条目）→ 四 agent 可见性留档或书面豁免”。四 agent 冒烟是 SHOULD 级一次性证据，不得将缺失 CLI、无法启动或未运行写成已通过；跳过时须记录 `SHOULD not-run`、原因和书面豁免。

发布平台前提：Linux 完整支持；macOS 需先安装 `bash>=4` 与 GNU coreutils，否则安装会失败。

安装脚本失败时必须保留用户文件，报告失败阶段和恢复建议；不能以“链接已创建”代替四类 Agent 的实际可见性验证。
