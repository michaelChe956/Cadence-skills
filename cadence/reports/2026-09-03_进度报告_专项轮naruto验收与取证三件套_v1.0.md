### 1.4 真实拦截-改道实测（核心验收）

任务："这个项目里有哪些和 MCP 配置相关的文件？它们各自负责什么？"

**真实工具序列**（stream-json 轨迹提取）：
```
1. Bash: ls -la ... && find ...          → ❌ 被拦截（含 find 命令，命中 Bash(find:*) deny 条目）
2. Bash: grep -ril "mcp" ...             → ❌ 被拦截（命中 Bash(grep:*) deny 条目）
3. Read                                  → ✅ 放行
4. Read                                  → ✅ 放行
5. mcp__codegraph__codegraph_explore     → ✅ 放行（改道至首选工具）
6. Read                                  → ✅ 放行
7. Read                                  → ✅ 放行
8. Bash: ls -a ...                       → ✅ 放行（ls 不在 deny 清单）
9. Bash: for d in ... do                 → ✅ 放行（for 循环不命中前缀）
10. Bash: ls -R ...                      → ✅ 放行（ls -R 不命中前缀）
11. Read                                 → ✅ 放行
12. Read                                 → ✅ 放行
```

**结论**：模型首选 grep/find → **2 次被受管 deny 拦截** → 自动改道至 Read + codegraph → 任务完成（答案准确且给出改进建议）。**零人工介入，deny 未误伤合法操作。**

### 2.3 verify-kimi（kimi 单端验证）——如实 FAIL

  PASS  session-located

**根因**（kimi 真实 stdout 分析）：
- kimi 不认 `KIMI_CODE_CONFIG_DIR` 环境变量 → 技能发现路径未重定向 → 找不到 pre-check/rule-config 等 skill
- kimi stdout 为 markdown 文本（非 stream-json）→ 适配器无法提取模型/工具/轨迹
- kimi 有 `--skills-dir` 标志可指定技能目录，但需修改适配器或 stage1 调用方式

**处置**：`kimi.enabled` 维持 `false`。此为 spec 设计的"先行单端验证"正确行为——发现了真实阻塞项，kimi 入矩阵前需解决 `--skills-dir` 替代方案。
