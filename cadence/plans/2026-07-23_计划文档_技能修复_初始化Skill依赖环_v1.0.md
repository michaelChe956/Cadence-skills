# 初始化 Skill 依赖环修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Change:** `fix-init-skill-dependency`（`openspec/changes/fix-init-skill-dependency/`，契约已获批）

**Goal:** 解除 pre-check 与 rule-config 的双向依赖环：pre-check 的 OpenSpec 验收不再依赖 `openspec/config.yaml`，增量分支改为按 claude/codex/pi 客户端产物检测，README 同步职责边界。

**Architecture:** 纯文档行为定义变更（Skills 项目，无代码实现）。斩断"pre-check 验收 → rule-config 产物"的反向边，保留"rule-config → pre-check 工具层"的正向边，依赖图由环变单向。TDD 在此适配为"grep 断言验证"：改前先证明旧口径存在/新口径缺失（失败态），改后证明反转（通过态）。

**Tech Stack:** Markdown 文档编辑；bash grep 验证命令（现有工具，不新写脚本）。

## Global Constraints

- pre-check MUST NOT 将 `openspec/config.yaml` 的存在性作为完成条件或失败条件（Spec: OpenSpec 检查完成门槛不含 config.yaml）
- config.yaml 缺失提示 MUST 为中文，且 MUST NOT 影响 OpenSpec 检查判定；no-interrupt 模式 MUST NOT 因此终止（Spec: config.yaml 缺失提示语义）
- 产物已齐全的客户端 MUST NOT 被重新 init；`openspec/config.yaml` 存在性 MUST NOT 作为分支判断条件（Spec: 按客户端检测的增量补齐）
- 六个基础检查的门槛地位 MUST 保持不变（Spec: 硬门槛与失败语义保留）
- 不修改 rule-config 的行为逻辑；pre-check 不创建 config.yaml；不对 `openspec init` 使用 `--force`（Proposal 非目标）
- 不编写任何代码或脚本；验证只用 grep/test 等现有命令（仓库代码使用规则）
- Markdown 嵌套代码块：外层 4 反引号、内层 3 反引号（仓库 markdown-format 规则）
- 所有交互输出文案 MUST 为中文（pre-check 强制规则 1）
