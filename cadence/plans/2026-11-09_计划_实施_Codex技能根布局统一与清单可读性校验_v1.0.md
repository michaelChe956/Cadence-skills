# 计划：实施 Codex 技能根布局统一与清单可读性校验 v1.0

- 关联 OpenSpec 变更：`2026-11-09-codex-skill-root-layout`（已 `openspec validate --strict` 通过）
- 契约来源：`openspec/changes/2026-11-09-codex-skill-root-layout/specs/network-skill-install/spec.md`、`.../specs/pre-check-scripted-execution/spec.md`
- 设计依据：`openspec/changes/2026-11-09-codex-skill-root-layout/design.md`（含 codex-cli 0.167.0 实测探针 A/B/D/E 与插件目录实测）
- 产物自动提交开关：关闭 → 本次不执行 `git commit`，只汇报路径

## 目标

1. Codex 用户技能层统一为 `~/.codex/skills/<skill>`（扁平），旧嵌套层 `~/.codex/skills/skills/` 受管链接自动迁移并迁空删除。
2. 安装器在同步后校验各层受管入口 `SKILL.md` 可读：可证明归属的重建，不可证明的告警 + 手动命令。
3. 安装器只读扫描 `~/.codex/skills` 全部入口，对不可读入口告警（不删除非托管内容）。
4. 共享层缺失时，下游层精确指向 `~/.agents/skills/<name>` 的遗留投影被清理。
5. pre-check 的 superpowers-links/verify 与安装器使用同一套 Codex 层路径与校验口径。

## 实施顺序（TDD）

1. **先写失败测试**（install.sh）：
   - T1 旧嵌套层迁移：`~/.codex/skills/skills/pre-check` → `~/.codex/skills/pre-check` 可解析，旧目录迁空后消失。
   - T2 共享层缺失后的下游清理：删掉共享层 `pre-check` 后重装，Claude/Codex 层同名链被清理。
   - T3 断链重建：受管条目 `SKILL.md` 不可读且所有权可证明 → 重建后可读。
   - T4 不可读且无法证明归属 → 告警 + 手动命令，条目不被删，安装继续。
   - T5 Codex 根扫描：`~/.codex/skills/superpowers/using-superpowers` 断链 → 告警列出路径与 `readlink` 目标；`~/.codex/skills/.system` 不告警。
2. 实现 install.sh 使 T1–T5 转绿。
3. pre-check 侧：先把集成测试基线里的 Codex 层路径改成 `~/.codex/skills`（红），再改脚本（绿）。
4. CI fixture 路径、文档同步。

## 验证命令

```bash
# 安装器：隔离 HOME 全流程 + shellcheck
shellcheck --shell=bash --severity=warning install.sh tests/test-install.sh
HOME="$(mktemp -d)" bash tests/test-install.sh

# pre-check：隔离 HOME 集成测试
HOME="$(mktemp -d)" bash tests/integration_pre_check.sh   # 具体入口以仓库脚本为准

# OpenSpec 契约校验
openspec validate 2026-11-09-codex-skill-root-layout --strict
```

## 风险与边界

- Codex 层路径变化会影响已安装机器：下次运行 `install.sh` / `/pre-check` 即完成迁移；旧层目录含非托管条目时保留并告警，不递归删除。
- `.system` 与插件缓存不属于本变更管理范围，扫描只读不删。
- 所有权证明不放宽到“前缀匹配”，第三方投影链存活是硬约束（既有 spec 场景）。
