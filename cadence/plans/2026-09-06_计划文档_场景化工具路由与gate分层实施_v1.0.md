# 2026-09-06 场景化工具路由与 gate 分层实施计划 v1.0

> **agentic workers 提示**：本计划要求采用 `subagent-driven-development`（REQUIRED SUB-SKILL），实施时每个 Task 独立、先测试后实现、完成后提交并由主代理复核。

## Goal
以九场景路由矩阵作为规则唯一规范源；默认 text 零 deny，safe/strict 显式启用；夜测分别度量文本路由与 gate 价值。

## Architecture
规则模板矩阵 → rule-config 解析/分发 → CLAUDE.md 决策卡投影；权限 gate 按 text/safe/strict 分流；eval fixture、probe、评分、报告形成三组实验矩阵。PreToolUse hook 仅预留。

## Tech Stack
Python 3、pytest、Markdown/YAML、Claude Code settings、CodeGraph/ast-grep、夜测 Python runner。

## Global Constraints
- 默认 `text` 模式必须零 deny；`safe` 仅参数可识别危险命令；`strict` 保留全量集合且仅 opt-in。
- 决策卡不超过 12 行；九场景矩阵必须置顶并作为唯一规范源，按“任务目标 > 对象类型 > 范围 > 时效性”裁决。
- 元数据 v2 仅含 `schema_version/default_mode/recommended_profile`；v1 可读但不得生成 deny，并提示升级。
- ❌ deny 文案条目废除；理由回归规则正文矩阵。
- `--remove-permission-gate` 三模式通用，区块外用户内容逐字不变；no-interrupt 不覆盖显式 allow。
- 不实现 PreToolUse hook，不改 MCP server 配置内容；夜测 trust 必须写入并断言无 `Ignoring ... permissions.allow`。
- 每 Task 严格 TDD：先写真实失败测试、验证失败、最小实现、验证通过、commit；禁止占位符、TBD。
