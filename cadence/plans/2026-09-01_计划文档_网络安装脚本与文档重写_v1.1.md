## Global Constraints

- `install.sh` 必须是单文件 Bash，并以 `set -euo pipefail` 启动；不得引入二进制安装器、Makefile、第三方运行时或 Windows 分支。
- 仅按固定顺序尝试以下三个 clone 镜像，并在首个成功后立即停止：`https://ghfast.top/https://github.com/michaelChe956/Cadence-skills.git` → `https://gh-proxy.com/https://github.com/michaelChe956/Cadence-skills.git` → `https://mirror.ghproxy.com/https://github.com/michaelChe956/Cadence-skills.git`；全失败必须以非零码退出，输出已尝试清单，不得直连 GitHub，不得进入离线模式。
- 仓库目标固定为 `~/.agents/Cadence-skills`（实现中使用 `$HOME/.agents/Cadence-skills`）；目标已存在且为 Git 仓库时必须 `fetch --all` 后解析 `origin` 的跟踪分支并执行 `pull --ff-only`，不得硬编码 `upstream` 或分支名；remote/fetch 失败必须轮换镜像，pull 非 fast-forward 失败立即报错。
- 目标存在但不是 Git 仓库时，必须原样保留目录，输出精确处理指引“请删除 ~/.agents/Cadence-skills 后重新运行”，并以非零码退出；不得静默使用、自动删除、复制覆盖或离线降级。
- 三层软链必须只覆盖含 `SKILL.md` 的 skill：`~/.agents/skills/<skill>` → 仓库 `cadence-init/skills/<skill>`；`~/.claude/skills/<skill>` 与 `~/.codex/skills/skills/<skill>` → `~/.agents/skills/<skill>`；三层父目录不存在时创建。pi 与 Kimi Code 消费共享层 `~/.agents/skills`，Claude Code 消费 `~/.claude/skills`，Codex 同时验证共享层与兼容层。
- **所有权证明必须是符号级、精确且安装/卸载同源：** 共享层条目仅当 `readlink` 精确等于 `$REPO_DIR/cadence-init/skills/<name>` 才算托管；Claude/Codex 层条目仅当 `readlink` 精确等于 `$SHARED_ROOT/<name>` 且 `readlink "$SHARED_ROOT/<name>"` 精确等于 `$REPO_DIR/cadence-init/skills/<name>` 才算托管。禁止以前缀匹配作为所有权依据；不能证明所有权的普通文件、普通目录、非受管软链及 dangling 第三方链必须告警跳过且绝不删除/覆盖。**谓词从当前前缀实现替换为上述精确证明的唯一落点是 4A.1 Step 3；Task 2 Step 1 只验证前缀实现，不提前写入替换代码。**
- 孤儿清理必须先在共享层计算托管且不在当前源集合中的待清 name 集合，再仅对该集合检查并清理 Claude/Codex 两层；不得按下游层前缀扫描直接删除。无法证明所有权的链只输出手动清理命令。
- 受管软链目标改变时必须使用同一父目录内不冲突的临时软链和 `mv -T` 原子替换；普通文件、普通目录和非受管软链保持原状并且不使安装失败。
- `--dry-run` 必须采用“计算动作计划 → 执行动作计划”两阶段：只计算并打印将 clone/update、创建、替换、清理、保留/告警跳过的动作，**不执行任何网络/git 操作、不创建目录、不写文件、不替换或删除链接**；真实执行必须消费同一计划逻辑，测试必须证明零落盘及计划/实装动作集合一致。
- **快照 diff 口径统一：** 对已存在条目 diff 为空；全新首装场景允许且仅允许新增链接条目。任何其他计划外删除、替换或内容变化都必须停止并回到隔离测试排查。
- `--uninstall` 仅删除三层中通过同一所有权证明的受管软链；只有 `--uninstall --delete-repo` 才删除 `$HOME/.agents/Cadence-skills`，且仅限可识别 Git 仓库；任何用户自建文件、目录和无法证明所有权的软链都不得触碰。
- 每次运行都要检测旧残留 `$HOME/.claude/plugins/marketplaces/cadence-skills-local` 与 `$HOME/.claude/plugins/known_marketplaces.json` 中的 `cadence-skills-local` 键；检测到即列出残留项并给出手动清理命令，绝不自动删除目录或修改 JSON。
- 成功输出必须分别说明 Claude Code、pi、Codex、Kimi Code 的消费路径与验证命令，至少给出 `ls ~/.claude/skills/`，并说明共享层及 Codex 兼容层的检查路径。
- 所有测试一律以 `HOME=$(mktemp -d)` 隔离；自动发布门禁包含 ShellCheck、首装、重复装、非 Git、更新镜像轮换、两条第三方投影红测转绿、dry-run 零落盘与计划一致性、卸载、14×3 链接矩阵；真实四 agent 可见性为 SHOULD 一次性人工验证，跳过时必须书面豁免。
- 文档任务必须严格覆盖整改基线：根 `README.md` 的 marketplace/install-offline/known_marketplaces/旧路径、错误 `/cadence-init:*` 调用名、七项缺失 skill、MCP 清单和四客户端路径混称；`readmes/` 七份文档必须按差异清单逐份核对；开发者知识文档放在 `cadence/readmes/`，并固化“dry-run → 人工核对 → 实装”流程。
- 所有文档中的 skill 调用统一使用实际裸名（例如 `/knowledge-base-context`、`/rule-config`），不得出现 `/cadence-init:*`；完整 14 个 skill 名称必须与 `cadence-init/skills/*/SKILL.md` 一致。
- **Task 2 基线约束：** Task 2 的同步与孤儿测试只验证当前前缀实现；精确 `readlink` 所有权证明及其替换仅在 `4A.1 Step 3` 执行，该步骤为全文唯一谓词替换落点。
- **真机重验必须按 Task 4A.5 的唯一顺序执行：** 三层链清单快照 → `--dry-run` 人工核对 → 实装 → 对已存在条目 diff 为空（全新首装场景允许且仅允许新增链接条目）→ 四 agent 可见性留档或书面豁免。Task 4A.5 是该真机序列的唯一执行点；Task 5 只复核其证据并补缺，不重复执行序列。
- `--dry-run` 仅预览安装；`--dry-run --uninstall` 预览卸载并保留仓库；`--dry-run --uninstall --delete-repo` 预览卸载和显式删除可识别 Git 仓库；三种形式都返回 0、只打印动作计划且零落盘。

- [ ] **Step 3: 写入使用临时目录的镜像轮换 clone 函数**

把以下函数加入 `install.sh`。临时 clone 成功后才 `mv -T` 到目标，保证三个镜像全部失败时目标目录既不创建也不残留半成品；`git clone` 的 URL 只能来自 `MIRRORS`，不得添加直连 URL：

```bash
clone_with_rotation() {
  if [[ -e "$REPO_DIR" || -L "$REPO_DIR" ]]; then
    fail "安装目标已存在，clone_with_rotation 不会覆盖：$REPO_DIR"
    return 1
  fi

  mkdir -p "$HOME/.agents"
  local staging_root url
  local -a attempted=()
  staging_root="$(mktemp -d "${TMPDIR:-/tmp}/cadence-skills-clone.XXXXXX")"

  for url in "${MIRRORS[@]}"; do
    attempted+=("$url")
    rm -rf -- "$staging_root/repo"
    log "尝试镜像：$url"
    if git clone "$url" "$staging_root/repo"; then
      mv -T "$staging_root/repo" "$REPO_DIR"
      rmdir "$staging_root"
      log "已从镜像安装到：$REPO_DIR"
      return 0
    fi
    warn "镜像失败：$url"
  done

  rm -rf -- "$staging_root"
  printf '[cadence][错误] 三个镜像均失败，已尝试：%s\n' "${attempted[*]}" >&2
  printf '[cadence][错误] 不使用直连 GitHub，也不提供离线安装。\n' >&2
  return 1
}
```

期望：代码中镜像顺序保持 `ghfast.top`、`gh-proxy.com`、`mirror.ghproxy.com`；成功分支在首个成功镜像后立即返回；全失败分支返回非零且不执行 `mv` 到 `$REPO_DIR`。

- [ ] **Step 4: 写入按 origin 跟踪分支更新的函数**

把以下函数加入 `install.sh`。它先尝试当前 origin URL（若当前 URL 不是三个镜像之一，则从第一个镜像开始），只有 `fetch --all` 失败才切换下一个镜像；fetch 成功后从当前分支的 `@{u}` 解析 `origin/<branch>`，再执行 `pull --ff-only`，不硬编码 `upstream` 或分支名：

```bash
update_repo() {
  local origin_url start_index=0 url tracking_ref branch
  local -a attempted=()

  origin_url="$(git -C "$REPO_DIR" remote get-url origin 2>/dev/null)" || {
    fail "仓库缺少 origin remote，无法执行 fetch --all / pull --ff-only：$REPO_DIR"
    return 1
  }

  for index in "${!MIRRORS[@]}"; do
    if [[ "$origin_url" == "${MIRRORS[$index]}" ]]; then
      start_index="$index"
      break
    fi
  done

  for offset in "${!MIRRORS[@]}"; do
    index=$(( (start_index + offset) % ${#MIRRORS[@]} ))
    url="${MIRRORS[$index]}"
    attempted+=("$url")
    log "使用镜像更新：$url"
    if git -C "$REPO_DIR" remote set-url origin "$url" && git -C "$REPO_DIR" fetch --all; then
      tracking_ref="$(git -C "$REPO_DIR" rev-parse --abbrev-ref --symbolic-full-name '@{u}' 2>/dev/null || true)"
      if [[ "$tracking_ref" != origin/* ]]; then
        fail "当前分支没有 origin 跟踪分支，无法安全执行 pull --ff-only"
        return 1
      fi
      branch="${tracking_ref#origin/}"
      if git -C "$REPO_DIR" pull --ff-only origin "$branch"; then
        log "仓库已 fast-forward 更新：origin/$branch"
        return 0
      fi
      fail "pull --ff-only 失败；请检查 origin/$branch 是否发生非 fast-forward 改写，必要时删除仓库后重新安装"
      return 1
    fi
    warn "remote 设置或 fetch --all 失败，继续轮换镜像：$url"
  done

  printf '[cadence][错误] 更新所需镜像均失败，已尝试：%s\n' "${attempted[*]}" >&2
  printf '[cadence][错误] 请检查网络；若 fast-forward 更新或远程历史被改写，请删除仓库后重新运行安装。\n' >&2
  return 1
}
```

期望：`awk '/remote (get-url|set-url)|fetch --all|pull --ff-only|@\\{u\\}/' install.sh` 只命中 `origin` 自适应逻辑；当前镜像的 remote 设置或 `fetch --all` 失败时按镜像清单轮换（从当前镜像开始并循环一次），`pull --ff-only` 因非 fast-forward 失败时立即返回非零并给出恢复指引。

- [ ] **Step 5: 写入非 git 拒绝与仓库选择函数**

把以下函数加入 `install.sh`，以 `git rev-parse` 判断目标是否为 Git 工作树；非 Git 目录、普通文件或目标软链均不删除、不覆盖：

```bash
ensure_repo() {
  if [[ -e "$REPO_DIR" || -L "$REPO_DIR" ]]; then
    if git -C "$REPO_DIR" rev-parse --is-inside-work-tree >/dev/null 2>&1; then
      update_repo
      return 0
    fi
    printf '[cadence][错误] 目标已存在但不是 git 仓库：%s\n' "$REPO_DIR" >&2
    printf '请删除 ~/.agents/Cadence-skills 后重新运行\n' >&2
    return 1
  fi
  clone_with_rotation
}
```

期望：目标是非 Git 目录时退出码非零，目录内容的校验和不变，输出逐字包含 `请删除 ~/.agents/Cadence-skills 后重新运行`；目标不存在时只调用 `clone_with_rotation`。

      sync_links

      elif (( $# == 2 )) && [[ "$2" == "--delete-repo" ]]; then
        uninstall 1
      else

        return 2
      fi

    --help|-h)

      print_help
