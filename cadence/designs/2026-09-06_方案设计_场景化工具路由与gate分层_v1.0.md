# 方案设计：场景化工具路由与 gate 分层（v1.0）

> 日期：2026-09-06
> 状态：待用户审批
> 依据：五份分析（analysis-nighttest-denials / analysis-test-architecture / analysis-gate-optimization / analysis-scenario-routing + scout gate 机制勘察，均在 `.superpowers/sdd/2026-09-04_计划文档_pre-check执行脚本化实施_v1.0/`）
> 用户决策：方向确认（2026-09-06 会话）

## 1. 背景与问题链

夜测取证暴露的四层问题，逐层递进：

1. **运行时层**：夜测考场未信任导致 settings allow 失效；❌ 引导文案模型不可见；headless 无人工授权出口。
2. **测试架构层**：现二组矩阵（control/installed）把"规则文本引导"与"物理拦截"混测——主指标（模型自觉遵循）从未被度量。
3. **gate 设计层**：规则元数据物化为全局无条件 deny，丢失任务场景语义——规则正文允许的合法场景（小文件直读/配置查询）被物理拦截（高误伤）。
4. **路由缺失层**：规则文本虽有场景指引但散落长文（335 行）、场景覆盖不全（Markdown 检索场景缺失）、无判断标准。

**根本约束**（实证）：Claude Code 权限系统只能按"工具/命令/路径"匹配，无法表达任务场景。判断"当前是什么场景"只有模型自身能做到。

## 2. 目标与非目标

**目标**：
- 工具选择准确率最大化：模型按场景自主路由到最优工具（首次工具选择正确率为主指标）
- 消除物理拦截误伤：默认产品形态=纯规则文本；gate 变 opt-in 且收窄
- 可度量：夜测能分别度量"规则文本价值"与"gate 价值"

**非目标**：
- 不追求权限系统实现"任务场景门控"（Claude Code 能力边界，做不到）
- 不在本期实现 PreToolUse hook 拦截（协议未实测，仅预留）
- 不改动 MCP server 配置本身（.mcp.json 内容不变）

## 3. 总体方案（四期）

```
期1 场景路由矩阵（规则文本重构，产品核心）
   └→ 期2 gate 分层（默认关 + safe opt-in + strict 回归）
        └→ 期3 夜测演进（三组矩阵 + 场景化探针 + trust 修复）
             └→ 期4 hook 增强（审计先行，实测协议后定）
```

## 4. 期 1：单源场景路由矩阵

### 4.1 场景枚举（九类，含判断信号）

| # | 场景 | 首选链 | 次选 | 判断信号 |
|---|---|---|---|---|
| D | 库/API/框架文档 | Context7 resolve→docs | 已知官方 URL→WebFetch；无 Context7→WebSearch | 库名、import、版本/API、官方文档诉求 |
| R | 开放调研/实时信息 | WebSearch→WebFetch 精读 | webSearchPrime/web_reader MCP | "最新/新闻/比较/业界/实时"、无固定来源 |
| C | 代码结构/调用链 | CodeGraph explore→ast-grep outline→定向 Read | 无图时 rg/Glob | 跨文件、调用链、架构、影响面、全仓 |
| M | Markdown/配置文本 | rg/Grep→Read；路径已知直接 Read | Glob→Read | 对象是 .md/.yaml/.json/.toml、明确字符串、小范围 |
| S | Shell/日志排查 | Bash（tail/sed/jq/awk） | Read 已知日志；窄范围 rg | shell 命令、stderr、日志、进程/环境 |
| G | Git 历史考古 | Bash git log/blame/show/diff | rg 查提交文本 | commit、回归引入、作者、历史 |
| T | 测试失败定位 | Bash 跑测试→Read/rg 错误→C 场景工具 | sequential-thinking（复杂多层） | test、stack trace、失败断言 |
| F | 文件路径发现 | Glob；小范围 find | rg --files、CodeGraph | "哪里/哪些文件/目录结构/模式匹配" |
| U | 已知 URL 精读 | WebFetch（或 web_reader） | Read 本地副本 | 用户给出 http(s)://、要页面正文 |

冲突优先级：任务目标 > 对象类型 > 范围 > 时效性；允许组合（如 T 先 Bash 后 C 工具）。

### 4.2 载体与文件布局（三层，单源）

1. **规范源**：`.claude/rules/code-reading.md` 重构——顶部放九场景路由矩阵（Markdown 表格），正文保留使用细节（ast-grep 参数/CodeGraph 工作流）；`mcp-servers.md` 的检索路由段并入或交叉引用该矩阵（消除两文件重复与漂移）。
2. **决策卡**：`CLAUDE.md` 顶部 8-12 行极简卡（"先判断场景：跨文件代码→CodeGraph；md/配置→rg；库名→Context7；URL→WebFetch；实时→WebSearch；日志→Bash；历史→git"）。
3. **机器元数据**：规则文件顶部 YAML 只保留稳定字段（`schema_version`/`default_mode: text`/`recommended_profile: safe`），**不再含 fallback deny 列表**；生成器从 Markdown 矩阵单源校验（快照测试防漂移）。

### 4.3 rule-config 适配
S3 规则分发同步新版文件；`parse_tool_metadata` 兼容新 schema（旧 fallback 字段废弃，向后兼容读取但不再用于 deny 生成）。

## 5. 期 2：gate 分层

| 模式 | 内容 | 启用方式 |
|---|---|---|
| **text（默认）** | 无任何 deny 生成 | 默认安装即此形态 |
| **safe（opt-in）** | 仅收窄窄面：**只含参数可识别的危险命令形态 deny**（递归删除/敏感路径覆盖类）；WebSearch/WebFetch 不 deny（R 场景它们是首选，实证高重叠拦不住且误伤调研） | `--enable-permission-gate=safe` |
| **strict（回归）** | 现行全量 deny（7 项） | `--enable-permission-gate=strict`，仅供实验/夜测 smoke |

变更点：
- `collect_permission_gate_entries` 按模式生成；safe 模式代码类 5 项 deny 全部移除
- `--remove-permission-gate` 保留（任何模式可撤销）
- ❌ 文案条目废除（实证模型不可见）；deny 理由改由规则文本承担
- spec：`openspec/specs/permission-gate-projection/spec.md` 修订（默认行为反转+模式定义+旧 settings 迁移：检测到无模式标记的旧 gate 区块时提示用户选择）

## 6. 期 3：夜测演进

### 6.1 三组矩阵

| 组 | fixture | 测什么 |
|---|---|---|
| control 裸 | 无规则无 gate，全工具预授权 | 基线 |
| installed-text | 规则栈（期 1 新版），无 deny，全工具预授权（含 codegraph） | **主指标：自觉路由** |
| installed-gate-safe | 规则栈+safe gate | 对照：拦截正确性/改道/兜底价值 |

（strict gate 每探针 1 次低频 smoke；会话量 16→24+smoke）

### 6.2 场景化探针（P1-P8 演进）

探针按场景重编：D/R/C/M/S/G/T/F/U 各至少 3 例（正例断言首选工具、反例断言不误伤——如 M 场景用 rg 不得被拦）。评分五指标：`first_tool_accuracy`（主）/`task_completion`/`route_recovery`（失败改道）/`false_positive_block`（误伤率）/`denial_count`。

### 6.3 前置修复（trust）
夜测 fixture 启动前写入 `hasTrustDialogAccepted` 信任标记 + 启动断言（stderr 不得出现 `Ignoring ... permissions.allow`）；argv 白名单补 `mcp__codegraph`。

## 7. 期 4：hook 增强（预留，先审计后拦截）

PreToolUse hook 实测协议（allow/deny/ask 返回字段、模型可见性）→ 先纯审计模式（记录工具选择 vs 路由表期望，不干预）→ 数据证明增益后对高置信错误形态软提示→ 最终仅对危险命令硬拦。**不承诺任务语义理解**。

## 8. spec 变更清单

1. `permission-gate-projection`：默认反转+三模式+元数据 schema v2+迁移
2. 新 spec（建议）`scenario-tool-routing`：九场景矩阵为规范契约（场景枚举/首选链/判断信号/冲突优先级），规则文件为其投影
3. 夜测矩阵定义（eval 侧验收口径）：三组/探针场景化/五指标

## 9. 风险与边界

| 风险 | 缓解 |
|---|---|
| 路由表注意力仍被稀释 | 决策卡极简（≤12 行）+ 矩阵置顶；夜测 first_tool_accuracy 度量并迭代 |
| 默认关 gate 后违规无兜底 | 主指标数据先证明文本有效性；strict 保留可 opt-in；期 4 hook 补参数级兜底；safe 窄面（危险命令）兜底破坏性风险 |
| 规则文件重构迁移（旧项目） | rule-config apply 幂等重分发；元数据 schema 兼容读取 |
| 九场景边界模糊（C vs M 判断） | 判断信号操作化+正反例探针校准；矩阵迭代机制 |
| hook 协议不可用 | 期 4 整体可弃，前三期不依赖 |

## 10. 验收

- 期 1：九场景矩阵+决策卡落盘；规则快照测试；现有 rule-config 测试全绿
- 期 2：三模式生成器测试（safe 无代码 deny/strict 全量/text 零 deny）；迁移路径测试；spec validate strict
- 期 3：三组夜测跑通（trust 断言生效/无 Ignoring stderr）；五指标落报告；M 反例（rg 不被拦）通过
- 期 4（若做）：审计 hook 数据+增益评估报告
