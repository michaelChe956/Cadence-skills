## 1. 背景与问题

业务项目使用 Cadence-skills 后观察到三类违规：

1. **①跳 workflow**：不写 spec 就 plan、不 plan 直接改代码；
2. **②不用 codegraph/ast-grep**：规则要求优先的代码检索方式被 grep/整读替代；
3. **③该用 MCP 不用**：规则声明的 MCP 调用路径被绕过。

实验与调研确定的归因链：

- 四端 L0 路由区块**内容**均已进入上下文（"完全没加载"假设否定），违规主因是"加载了但不遵守"→ 需要强制面，继续堆提示词收益有限；
- **Claude Code 注入上下文时剥离 HTML 注释**，`cadence-managed` 版本标记对其不可见，自检/回执无法报版本；
- **Codex 不读 `.claude/rules/` 目录**，②③类规则在其上下文中只有文件名、没有内容——②③在 Codex 上是加载问题；
- 本仓库现状零 hook、零行为拦截，全部约束为提示词软约束。

## 3. 总体架构

### 3.1 规则即唯一事实源，按 harness 分级投影

```
规则模板（带机器可读元数据，preferred/fallback/适用条件）
  │ rule-config apply 读取
  ▼
按项目实际配置生成各端投影：
  ├→ Claude Code：.claude/settings.json 的 cadence-managed permissions 区块（fallback 工具 deny；优先级链文本以惰性条目留存区块内，主要随规则正文常驻）
  ├→ Codex/Kimi：AGENTS.md 的 cadence-managed:codex-rules-inline 受管区块（压缩规则文本）
  └→ （切片 2）pi：项目扩展 tool_call 拦截器读同一元数据
诊断层：rule-config --verify 校验所有投影与源无漂移（退出码可编程判定）
```

### 3.2 分级保护矩阵（subagent×MCP 现状一并固化）

| 端 | 主会话 MCP 配置来源 | 子代理 MCP | 本期动作 |
|---|---|---|---|
| Claude Code | `.mcp.json`（mcp-configuration 维护） | ✅ 默认继承 | 验证探针（防已知继承 bug） |
| Codex | `.codex/config.toml` 同步 | ✅ 默认全量继承 | 无需动作，文档说明 |
| Kimi | `.mcp.json`（原生三层加载） | ✅ 默认保留全部工具 | `tools` glob 写法坑指引 |
| pi | `.mcp.json`（pi-mcp-adapter 读取） | ❌ 不继承（已知限制） | 规避策略：MCP 依赖任务留主会话 |

## 4. 工作包设计

### WP1：`rule-config --verify` 加载自检（4–8h）

新增只读子命令，检查业务项目五项并输出结构化报告 + 退出码（0=健康，1=漂移）：

1. AGENTS.md/CLAUDE.md 的 L0 区块版本（v1/v2/v3/v4 + 是否最新）；
2. 7 个受管规则文件与模板哈希比对；
3. 权限投影区块 vs 规则元数据重算结果（依赖 WP2）；
4. codex-rules-inline 区块 vs 源重算结果（依赖 WP4）；
5. 三层软链解析是否指向 Cadence 源。

约束：纯只读，不修改任何文件；输出机器可解析（JSON 可选），使其可直接作为目标 B 的 Tier-0/L1 断言原语。第 3/4 项对从未生成过投影区块的项目报"未生成"（提示运行 apply），不报漂移；仅当区块存在且与源重算结果不一致时报漂移。

### WP2：规则元数据 + 权限投影，仅 Claude Code（6–10h）

**元数据格式**（挂在规则模板的受管注释区，人话正文不变）：

```yaml
# 示例：code-reading-coding.md 头部受管注释
cadence-tools:
  - preferred: [codegraph, "ast-grep outline"]
    fallback: [Grep, Glob, "Bash(grep:*)", "Bash(rg:*)", "Bash(find:*)"]
    when: project_type=coding AND codegraph_enabled
# 示例：mcp-servers.md
cadence-tools:
  - preferred: [Context7]
    fallback: [WebSearch, WebFetch]
    when: context7_configured
```

**生成规则**：`rule-config apply` 读取元数据 → 对 `when` 条件成立的条目，把 `fallback` 工具写入 `.claude/settings.json` 的 `permissions.deny`；区块以 `cadence-managed:permission-gate:v1` 标记包裹（**区块级受管，绝不整文件覆盖**，与既有 L0 机制同构）；dry-run 先预览；`--remove-permission-gate` 整体撤销；逃逸路径：Bash 域 `CADENCE_BYPASS=1` 前缀绕开（环境变量全量放行属切片 2 PreToolUse hook，本期机制不读环境变量）。项目未配置的规则不产生任何拦截。

**优先级链文本（常驻规则正文，deny 的配套，从同一元数据渲染，规则改→链文本同步变）**：

Claude Code 原生 deny 只回通用文案（issue #87153），拦截反馈不携带链；链文本随规则正文常驻上下文（.claude/rules/ 模板正文 + AGENTS.md 内联区块的元数据优先级链行），另以 deny 区块内惰性条目供 /permissions 面板读取：

```text
❌ Grep 被规则限制。规则优先级链：
1）大范围代码检索 → codegraph
2）精读文件结构 → ast-grep outline
3）前两者确不适用时 → rg 定向搜索
请按此顺序重试；确需例外：--remove-permission-gate 整体撤销，或 Bash 域以 CADENCE_BYPASS=1 前缀绕开。
```

设计意图：模型被通用 deny 拦下后，在上下文规则正文中查到完整合法路径，自动改道 preferred 工具，无人工弹窗；逃逸出口写进链文本末尾（Bash 前缀绕开本期可用，环境变量全量放行属切片 2），防止边角场景卡死。

**元数据扩展点**：`preferred` 字段同时供切片 2 的 pi 扩展与规则正文渲染使用，本期只消费 `fallback` 与 `when`。

### WP3：L0 v4 可见版本行（1–2h）

- 模板区块首行增加可见文本 `Cadence L0 路由内核 v4`（HTML 注释标记保留，供脚本解析与受管识别）；
- `L0_CURRENT_VERSION=v4`，沿用既有权威覆盖升级链（v1/v2/v3 → v4），历史版本归档进 `l0-history/`；
- 动机：Claude Code 剥离 HTML 注释（实验发现 2），版本标记必须以可见文本形式存在，回执才能自报版本。

### WP4：Codex 规则自动内联投影，A+ 方案（4–6h）

- 唯一源 = `.claude/rules/*.md` + WP2 元数据；`rule-config apply` 自动生成/覆盖 AGENTS.md 的 `cadence-managed:codex-rules-inline:v1` 受管区块；
- 内容：优先级声明（preferred/fallback 压缩版）+ 铁律摘要，预算 ≤60 行（超出时按元数据优先级截断并在末尾标注省略）；

- 已接受代价：pi/Kimi 同读 AGENTS.md，与 `.claude/rules/` 内容重复约 1.5KB 上下文；
- 依据：Codex 官方无 AGENTS.md 之外的自动加载机制（源码级确认），社区主流即"片段源 → 生成 AGENTS.md + drift 校验"。

## 7. 验收场景（EARS 概要，OpenSpec specs 展开）

1. WHEN 业务项目 L0 为 v3 且运行 `--verify` THEN 报告"版本过时（当前 v3，最新 v4）"且退出码 1；
2. WHEN coding 项目启用 codegraph 且运行 apply THEN `.claude/settings.json` cadence-managed 区块内 fallback 检索工具进入 `deny`，区块外用户自定义内容不变；
3. WHEN 项目未启用 codegraph 或为非 coding 项目 THEN 权限区块不生成任何检索类 deny 条目；
4. WHEN Claude Code 会话尝试 Grep 且存在 deny 条目 THEN 工具调用被通用 deny 文案阻断（反馈不携带链），模型从上下文规则正文查到规则优先级链与兜底出口后按链自动改道；逃逸：`--remove-permission-gate` 整体撤销、Bash 域 `CADENCE_BYPASS=1` 前缀绕开（环境变量全量放行属切片 2）；
5. WHEN apply 后修改任一规则源文件再运行 `--verify` THEN 对应投影项报告漂移且退出码 1；
6. WHEN 维护者新增规则文件并重跑 apply THEN codex-rules-inline 区块自动更新且 ≤60 行；
7. WHEN 任意端子代理被派"列出 MCP 工具"探针 THEN Claude Code/Codex/Kimi 报告继承的工具，pi 报告无（已知限制）并按兜底链规则提示主会话接手。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| settings.json 区块合并破坏用户自定义内容 | 区块级受管标记 + 专用合并/撤销测试用例 + dry-run 预览 + 备份到 cadence/legacy/ |
| deny 在规则未覆盖的边角场景致模型反复撞墙 | 链式拒绝理由写全 preferred→次选→兜底出口；`CADENCE_BYPASS=1` 逃逸写进理由末尾；观察期收集撞墙案例迭代理由文案 |

| pi/Kimi 上下文重复 1.5KB | 已接受（维护者拍板）；切片 2 的 pi 扩展可改为按需注入时再优化 |
| Claude Code 继承类 bug 导致探针误报 | 探针失败仅告警不阻断；输出排查指引（用户级配置替代方案） |

| 规则元数据格式设计失当返工 | 元数据只消费 fallback/when 两字段起步，扩展点留白 |

## 12. 切片 2 预留设计记录：PreToolUse 时序门禁（攻违规①）

本期明确不做，设计要点记录如下，供切片 2 立项时直接取用：
