## 1. 背景与问题链

1. **omp 端盲区**:`.omp/AGENTS.md` 出现前 omp 会话只见 `.claude/CLAUDE.md` 的 10 行 CodeGraph 块;规则层 `.claude/rules/` 不在 omp rulebook 扫描范围,无 frontmatter 的规则进不了任何桶=omp 侧不存在。
2. **Claude 端反向极端**:`.claude/rules/*.md` 无 frontmatter → 启动时全量强载(实测 InstructionsLoaded 审计:8 文件全部 session_start 载入,含 8.7KB 的 mcp-servers.md)。
3. **Codex/Kimi/pi 无规则目录概念**:规则正文只能经 AGENTS.md(全文常驻,32KB 预算)或行为指针(读文件)到达。
4. **单一事实源缺位**:同一规则要五端生效需要多份副本;`.omp/AGENTS.md` 的 CodeGraph 块副本随 codegraph 再生成滞后(双副本漂移)。
5. **rule-config 客户端语义缺 omp**:L0 路由块只有 Claude/Kimi、Codex、pi 三类语义。

**A(选定)`.claude/rules` 单一物理源 + `.agents/rules` 文件级软链桥 + `.omp/AGENTS.md` 受管活引用**

- 规则物理文件唯一于 `.claude/rules/*.md`(RF-05 权威覆盖管线不动);模板增加共享 frontmatter。
- omp 桥:`.agents/rules/<名>.md → ../../.claude/rules/<名>.md` 相对软链(omp 70 优先层,实测全通)。
- `.omp/AGENTS.md` 受管化为活引用:`@../.claude/CLAUDE.md` + `@../AGENTS.md`(codegraph 再生成→omp 自动跟随,零副本)。
- Codex:沿用 s10 `codex-rules-inline` 受管区块(已存在);Kimi/pi:根 `AGENTS.md` 指针节 + L0 行为路由(现状已指针式,按需 read)。
- R2「改一处五端生效」:Claude/omp/Kimi/pi 即时;Codex 经 `/rule-config` 重跑(既有受管再生成哲学)。

**B 生成式投影**(否决为独立方案,收编为降级):rule-config 生成 `.omp/rules/*.md` 副本。Windows 安全,但正文双份=漂移面,「改一处」变「改一处+重跑」。→ 作为 A 的 fallback:symlink 创建失败时物化副本+warning(见 §6.3)。

## 4. 共享 frontmatter 契约(单一文件服务多端)

```yaml
---
description: <一句话:omp 索引行 + 人类目录说明>   # omp:索引+rule://;Claude:忽略(剥离)
paths: ["**/*.rs", ...]                       # Claude:条件加载触发;省略=常驻;omp:忽略(实测容忍)
agents: [...]                                  # 可选能力:omp agent 过滤;框架模板不使用(Claude 忽略)
---
```

各字段单一职责、互不冲突:omp 读 `description`/`alwaysApply`/`agents`,Claude 读 `paths`,无端会因他端字段改变分桶(实测交叉容忍)。

## 5. 分桶默认值(8+1 文件逐一定档)

| 规则文件 | Claude 桶 | omp 桶 | 依据 |
|---|---|---|---|
| `language.md`(3 行) | 常驻(无 `paths`) | `alwaysApply: true` | 每次交互生效;体积极小,常驻成本可忽略 |
| `code-usage.md` | `paths`=源码扩展名 | 索引 | 触码即载 |
| `code-reading.md` | `paths`=源码扩展名 | 索引(默认无 `agents`=全 agent 含 scout 可达) | R3:默认可达 scout,无需显式枚举 |
| `document-storage.md` | `paths`=`**/*.md`、`cadence/**` | 索引 | 写文档时 |
| `markdown-format.md` | `paths`=`**/*.md` | 索引 | 写 Markdown 时 |
| `playwright.md`(可选) | `paths`=e2e/web 路径 | 索引 | 可选文件 |
| `mcp-servers.md`(8.7KB) | `paths`=图片/媒体 glob(`**/*.png`、`**/*.jpg`、`**/*.jpeg`、`**/*.webp`、`**/*.gif`、`**/*.svg`) | 索引 | 触图自动载图片识别路由;web-search/浏览器部分靠 L0 必读;**摘掉强载**(用户已确认) |
| `openspec-superpowers-workflow.md`(5.1KB) | `paths`=永不匹配 glob(仅 L0 路由读) | 索引 + `agents: [main]` | L0 首行已强制读;子代理不路由;R3 真实验收样本(用户已确认) |
| `README.md`(目录页) | 常驻 | **不桥接** | R5 允许目录页级常驻;不作为规则暴露 |

> 「源码扩展名」口径:`code-usage`/`code-reading` 双源模板按项目类型分化——coding 落地源给 glob=`SOURCE_EXTS` 常量(13 个扩展名)口径 + `tsx`/`jsx`/`vue` 增补(共 16 条);non-coding 落地源给永不匹配 glob(退化为行为路由桶,与 `openspec-superpowers-workflow.md` 同法)。

永不匹配 glob 的写法在文件内注释标注意图(「条件桶占位:本规则经 L0 路由必读,不自动注入」),防读者误解。
