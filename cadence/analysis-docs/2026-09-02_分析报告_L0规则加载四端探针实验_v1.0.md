- **日期**：2026-09-02
- **样本项目**：`/home/michaelche/workspace/github/naruto`（业务项目，Cadence 已安装）
- **实验目的**：验证 oracle 决策咨询提出的"实验 1：规则加载实证"——在归因"模型不听话"之前，先证明规则确实进入了各 harness 的上下文
- **方法**：四端无头探针（`claude -p` / `codex exec` / `pi -p` / `kimi -p`），同一提示词三问（复述 L0 区块含 HTML 注释标记 / 列出生效的 `.claude/rules/` 文件 / 答产物自动提交开关），要求"只凭已加载上下文、禁止调用工具"
- **判卷基准**：naruto `AGENTS.md` 中 `cadence-managed:openspec-superpowers-routing:v3` 区块（2501 字节），关键锚点：铁律（失败关闭）行、产物自动提交开关行（正确答案：关闭）

## 二、关键发现

### 发现 1：L0 内容四端均已进入上下文——"完全没加载"假设在 naruto 上被否定

四端第 3 问全部答对（"关闭"该信息仅在 L0 区块与 CLAUDE.md 尾部配置区），证明 L0 区块内容已被各端吸收。违规主因从"规则没进上下文"收窄为"**进上下文了但不遵守**"（长上下文稀释 / 弱模型遵循率）。

> 推论：oracle 方案 2（PreToolUse 时序门禁）与方案 3（权限层强制）的优先级得到确认——继续堆提示词收益有限。

### 发现 2：Claude Code 注入上下文时剥离 HTML 注释，版本标记机制对其失效

Claude Code 自述："加载了 CLAUDE.md 的「OpenSpec 与 Superpowers 任务路由」章节，但其内容不带有任何 HTML 注释起始/结束标记"。即 `cadence-managed:...:v3:start/end` 版本标记在 Claude Code 上下文中不可见：

- agent 无法自报 L0 版本 → 路由回执无法含版本自检；
- 任何依赖模型读取标记做版本判定的机制在 Claude Code 上失效。

> 修复候选（低成本）：rule-config 模板在区块首行增加可见文本版本号（如"Cadence L0 路由内核 v3"），保留 HTML 注释标记供脚本解析。

### 发现 3：Codex 不加载 `.claude/rules/` 目录——违规②③在 Codex 上确实是"规则没加载"

Codex 列出的 7 个文件名与 CLAUDE/AGENTS.md 文本引用集完全一致（未列 serena-usage.md、README.md），证明其只认 AGENTS.md 内联文本，**不读取 `.claude/rules/` 目录内容**。code-reading.md（codegraph/ast-grep 优先级）与 mcp-servers.md（MCP 触发规则）在 Codex 上下文中只有文件名、没有规则内容。

> 修复候选：rule-config 为 Codex 生成关键规则内联投影（写入 AGENTS.md 或 `.codex/` 专属文件），或接受 Codex 端降级。

### 发现 4：Codex 复述被污染——上下文存在跨源合并

Codex 多出的"不引导 knowledge-base-bootstrap"不在 naruto AGENTS.md 基准中，也不在全局 `~/.codex/AGENTS.md`（无该区块），疑似来自其 skills 清单中 knowledge-base-context 的 description。项目权威内容可能被其他上下文源稀释。

### 次要观察

- Kimi stderr 泄露完整内部推理（harness 层缺陷，不影响本实验效度，但值得单独记录）。
- naruto `.claude/settings.json` 已存在第三方（codegraph）的 `UserPromptSubmit` hook 与 `mcp__codegraph__*` 全量 allow——与方案 3 的权限层思路同构，是该方案可落地的本机先例。
- Claude Code CLI 实际运行模型为 `glm-5.3-flash[1M]`（弱模型），符合"弱模型遵循率低"的测试场景；本实验同时证明了 harness 行为与模型行为可分离观测。

## 三、对目标 A / B 的影响

1. 归因结论（naruto 单样本）：违规①②③主因是"加载了但不遵守"，其中 **②③在 Codex 上是"规则没加载"**（发现 3）。
2. oracle 起手顺序 1→3→2 维持，新增两个微修复候选进入 OpenSpec 切片范围：L0 可见版本行（发现 2）、Codex 规则内联投影（发现 3）。
3. 目标 B：本实验本身即可固化为 Tier-0 冒烟 eval 的原型（四端探针 + 逐字比对 + 退出码），成本低（4 次短调用）、可重复、判卷可程序化。
