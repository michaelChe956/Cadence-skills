# Subagent 协作协议

> 适用范围：所有项目的 subagent 派工与执行。
> 本文件只含**跨项目恒真**的纪律；项目专属的命令、路径、架构约束见项目级规则。
> 角色与模型指派见 `rule://subagent-roster`（仅主会话可见）。

## 一、编排铁律（controller / 主会话职责）

1. **尽量用 subagents 工作，controller 只做编排、裁决整合与最终验证。** 读代码、分析、实现、审查、写计划文档全部派出去，保主会话上下文不满。
2. **计划文档必双审后才开工**：接地审查（实现可行性）+ 一致性裁决（与既有决策不冲突），两者并行。发现按裁决注入后续派工。
3. **每个 Task 闭环**：实施（TDD 红→绿）→ 独立审查 → findings 进 fix loop（≤5 轮：前 3 轮续派原实施者，后 2 轮换更强模型全新派工；每轮修复 + 范围化复审）→ 终审（全量 diff + 挂起项分诊）→ 一轮修复波收口。
4. **续任务一律全新自含派工**，携带状态恢复指引与裁决注入；**禁裸 resume**（子代理不继承历史，裸 resume 等于让它空手上阵）。
5. **能并行的尽量并行，不设并行度上限。** controller 主动寻找并行机会：
   - **实施并行**：计划期按文件面切分边界，同段内串行；每组 worker 明确「独占文件清单 + 禁碰清单」。
   - **流水线并行**：T(N) 实施 ∥ T(N-1) 审查 ∥ T(N+2) brief 预备，三线常态重叠。
   - **审查并行**：审查只读无冲突，可开多实例并行审不同 Task；扩实例不等于换人（模型不变）。
6. **并行 worker 活跃时 controller 禁 `git add -A`**（曾因此丢失并行方改动）。worker 提交一律显式列文件。
7. **审查角色不可用时通知用户，不自主降级或换人**（扩实例不属换人）。超时不等于失败：先核对文件是否已改再决定重派。
8. **大任务设时长上限并勤提交**；worker 裸奔过久时 controller 主动 DM 催分批提交。
9. **真实跑绝不伪造，绝不用 dry-run 冒充真实执行。** 验证必须有命令与输出证据；新形态缺口停下原样记录，等用户裁决，不要猜着填。

## 二、并行机会识别

| 时机 | 并行模式 | 判定依据 |
|---|---|---|
| 计划期 | 按文件面切分实施段 | Task 的文件清单无交集 → 可分组并行 |
| Task 间 | 流水线三线重叠 | T(N) 实施完成即派 T(N-1) 审查 + 预备 T(N+2) brief |
| 审查期 | 审查者多实例 | 不同 Task 的 diff 互相独立 |
| 契约 / 计划期 | 接地审查 ∥ 一致性裁决 | 双审并行（铁律 2 标配） |
| 测试期 | 多 subagent 并行 + controller 收口 | 各自只写自己的输出目录 |

## 三、派工纪律（brief 必含项）

每个并行 worker 的 brief 必须写明：

- **独占文件清单** —— 只许改这些。
- **禁碰清单** —— 并行方正在改的文件。
- **有阶段性成果立即分批 commit**，显式列文件。
- 跨任务契约（接口、schema、数据格式）在批次 context 里定好，不留给 worker 之间自行协商。

worker 之间**不直接协调文件归属**，一律归 controller 仲裁：先问归属再动工。发现读到的内容与磁盘不一致（缓存漂移）时，先重读最新文件再判断。

## 四、git 安全协议

- 禁抹除性操作：`reset --hard`、`revert`、`clean -f`、强推、`branch -D`，除非用户显式批准。
- **冲突回退 stash 三步协议（缺一不可）**：
  1. stash 前 `git status` 快照 + 涉事文件清单记录在案；
  2. stash 后核对工作树仅剩另一方改动；
  3. pop 后逐文件 diff 核对无丢失再继续。
- 提交只暂存明确属于本次任务的文件；疑似含密文件（`.env`、凭据、token）提交前必须先报告。

## 五、Worker 报告契约

返回 controller 的内容必须包含：

- **状态**：`DONE` / `DONE_WITH_CONCERNS` / `NEEDS_CONTEXT` / `BLOCKED`。
- **commit 列表**（显式文件）。
- **一行验证摘要**：跑了什么命令、结果如何。
- **concerns**：自查发现的缺陷、被阻断项、与规则冲突处。

规则要求：

- 报告写盘路径遵循项目级规则；**不要 `git add` 报告文件**（已被 track 的文件 `.gitignore` 不生效）。
- 实施者自己发现缺陷可以**先修后报**，但报告必须如实记录修了什么。
- 未验证的结论一律标注为未验证，禁止把推测写成已验证事实。

## 六、被派工时的自我约束（worker 视角）

1. **超范围即停**：发现需要改动 brief 未授权的文件、接口或架构边界时，停下并上报，不要自行扩权。
2. **歧义即问**：brief 与代码现状矛盾、或有两种合理解法且影响验收时，上报而不是猜。
3. **不缩范围**：不得以"先交一版"名义交付 stub、占位、mock、假降级。做不完就如实说明卡在哪。
4. **不扩范围**：不顺手重构、不加未要求的抽象、不做未要求的清理。
5. 验证自己的改动：跑定向验证并回报命令与输出，不要声称未实际观察到的结果。
