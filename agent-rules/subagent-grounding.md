# Subagent 接地协议

> 适用范围：所有 agent（含主会话与全部子代理），所有项目。
> 本文件只描述**如何发现**项目约束与工具能力，不包含任何项目专属内容。

## 一、为什么需要这一步

子代理以空上下文启动：**不继承对话历史，也不接收项目的 `AGENTS.md` / `CLAUDE.md` 正文**。
你在系统提示中能看到的项目约束，只有 `<domain-rules>` 里的规则清单（名称 + 描述）。
因此「我没被告知」不是免责理由 —— 清单就在你的提示里，正文用 `rule://<name>` 自取。

## 二、渐进式读取（核心机制）

1. `<domain-rules>` 清单里**只有名称和描述，没有正文**。这是设计使然：不为用不到的规则付上下文。
2. 需要某条规则时，用 `rule://<name>` 读取正文。读一条，不要全量拉取。
3. 判断依据是**描述**与你当前活动是否相关，不是文件名猜测。
4. 清单里没有的规则就是本项目未启用 —— 不要假设它存在，也不要按记忆套用其他项目的约束。

## 三、按活动类型决定读哪条

先扫自己的 `<domain-rules>` 描述，命中则读；未命中则按自身判断执行，不阻塞。

| 你即将做的事 | 找描述涉及以下主题的规则 |
|---|---|
| 跨文件检索、架构理解、调用链或影响面分析 | 代码阅读 / 检索工具优先级 |
| 写实现、改 Bug、跑测试 | 代码规范 / TDD / 构建与测试命令 |
| 产出 Markdown 文档或报告 | 文档存储路径与命名 / Markdown 格式 |
| 使用联网、图片识别、浏览器等外部能力 | MCP Server 与工具使用 |
| 被派工执行任务（并行边界、提交、报告） | Subagent 协作协议 |
| 走需求、设计、计划、审查、归档流程 | 流程路由与阶段门禁 |

## 四、工具发现协议（不要按名字假设）

**你的工具清单是唯一权威。** 它随项目和时间变化，规则正文提到的工具不一定在你手上。

1. 动手前先看自己实际拥有哪些工具，包括 `xd://` 设备与 MCP 工具。
2. 做大范围代码检索前，优先在清单中寻找**结构化代码智能工具**（代码图谱查询、AST 结构检索、语言服务器），它们比逐行文本搜索更准、更省上下文。
3. 清单里没有 = 当前不可用。**直接降级**到文本检索并继续，不要报错、不要停工、不要因此声称任务受阻。
4. 规则正文提到某工具但你没有，以**你的清单为准**，并在报告里记一句"规则建议 X，本会话不可用，已用 Y 替代"。
5. 同理，你清单里有但规则没提的工具，可以用 —— 规则是下限不是上限。

## 五、失败时的正确行为

- 规则读取失败：记录下来并按自身判断继续，不要因此终止任务。
- 规则之间冲突：项目级规则优先于通用规则；仍无法判断时停下并向派工方说明分歧点，不要自行选一边。
- 派工 brief 与规则冲突：brief 优先（它携带派工方的即时裁决），但必须在报告中指出这处冲突。
