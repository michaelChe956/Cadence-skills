## Context

本 change 是对 2026-09-04~05 已实施并完成 whole-branch 终审的 pre-check 脚本化改造进行追溯性契约固化。现状已经由单一 `pre-check.sh run` 统一承载基础工具、OpenSpec 投影、Superpowers Git、软链和 verify 五个阶段；本设计只把该行为边界、报告形状、失败语义与验收守卫记录为可持续维护的能力契约。

完整设计依据见 `cadence/designs/2026-09-04_design_pre-check执行脚本化_v1.0.md`。该文档详细记录了实测 6m38s 的耗时分解、五阶段职责、Bash 3.2 约束、镜像与 Git 候选策略、四端投影/四层软链兼容性、测试矩阵和 1:1 基线方法；本文件仅摘要关键决策，不复制全文。

## Goals / Non-Goals

**Goals:**

- 让一次脚本调用确定性完成五阶段编排，并输出下游可以直接断言的 `phases[]` 报告，同时保持既有 `steps[]` 向后兼容。
- 让 SKILL.md 只负责定位、一次调用和报告呈现，消除模型临场编排、临时 heredoc 和重复状态探测。
- 统一冷热启动性能验收线为 ≤120 秒，以 240 秒仅作为网络异常熔断上限。
- 固化普通模式与 `--no-interrupt` 的冲突、失败快返、只读 verify、幂等和兼容性基线语义。
- 通过隔离 fixture、阶段负向测试、真实验收与 `precheck-v2` 1:1 diff 守卫验证行为没有超出已实施范围。

**Non-Goals:**

- 不改变 `mcp-configuration`、`rule-config`、`project-rules-examples` 或其他非 pre-check 能力。
- 不修改 `init-skill-sequencing`、`kimi-code-support` 中现有 MUST；相关 O-1 张力不在本 change 解决。
- 不为冷启动另设更宽性能线，不把网络熔断时间当作合格性能目标。
- 不改变人工 fallback、Playwright 显式 opt-in、API Key 占位符和普通模式报告详尽度等既有边界。
- 不引入新的运行时依赖或将脚本实现细节提升为公共接口。

## Decisions

### 1. 用五阶段串行编排替代模型编排

阶段固定为 `base-tools → openspec → superpowers-git → superpowers-links → verify`。每阶段独立计时、独立计数和独立结果，主流程统一生成报告。这样既能保留各阶段错误上下文，又能使模型只消费稳定 JSON，而不是重新推导动作顺序。

备选方案是继续在 SKILL.md 中描述命令清单，或把全部动作拆成多次模型调用；前者无法避免跳步与拼写/分词错误，后者增加调用次数并扩大耗时，因此不采用。

### 2. 把三步 SKILL 契约作为唯一模型入口

模型必须定位 pre-check 脚本的绝对路径，在项目根目录进行一次 `run` 调用，再读取独占报告并呈现。镜像、`--no-interrupt` 和升级选择均作为脚本参数传入；模型不得重写安装、更新、Git 或软链命令。脚本报告中的 `unsupported` 或失败状态交由人工处理，不静默降级为模型自由编排。

备选方案是保留旧的逐项检查说明，或让模型读取后按阶段自由选择命令；两者均违背“动作可断言、调用 ≤5”的性能与可靠性目标。

### 3. 通过结构化报告承载兼容性与审计信息

报告保留原有 `steps[]`，新增每阶段的结果、动作、毫秒计时、写入/跳过/冲突计数和错误字段；Git 阶段额外给出 origin、branch 及前后 revision，软链阶段给出来源条目和层级信息。`skipped` 只表示零写入且无冲突，避免把实际变更隐藏在成功状态中。

备选方案是仅输出人类可读日志或只返回总 exit code；这无法支持阶段级验收、重跑幂等和失败归因，因此不采用。

### 4. 冲突以模式区分，但不静默

普通模式遇到同名非软链冲突时保留用户内容，记录 warning/skip 与冲突计数，继续后续阶段并统一 emit；`--no-interrupt` 采用备份→创建→验证链，链路全部成功才算 success，任一步失败才算 failed。普通冲突的“成功”不等于忽略冲突，报告必须可审计。

### 5. 将性能与基线守卫置于验收层

脚本的 240 秒预算只负责网络异常熔断；验收断言单独要求所有冷热场景 ≤120 秒。首跑和二跑均使用隔离 fixture，目标写入范围按契约白名单核对；`precheck-v2` 作为由旧实现、真实布局和本地 bare remote 重采的 1:1 行为基线，防止为迎合虚构布局而放宽判定。

## Risks / Trade-offs

- **[网络抖动]** Git 候选可能在 120 秒内无法完成 → 单候选与 phase 预算分层，240 秒只作熔断并明确标记基础设施失败。
- **[用户文件冲突]** 软链同名非软链可能包含用户内容 → 仅在 `--no-interrupt` 按备份后创建并逐步验证；普通模式保留原内容并以 warning/skip 呈现。
- **[旧消费方兼容]** 下游仍只识别 `steps[]` → 保留原字段，同时让新断言消费 `phases[]`，不删除旧字段。
- **[平台差异]** macOS Bash 3.2 缺少现代 Bash 特性 → 候选使用普通 indexed array，避免关联数组、`mapfile`、GNU-only 工具和其他禁用特性，并以 zsh/fixture 测试覆盖。
- **[基线误导]** 旧采集器或虚构目录可能掩盖实现回归 → 只采用 `precheck-v2` 真实布局、本地 bare remote 和固定守卫；作废基线不得作为验收证据。
- **[O-1 规范张力]** 其他 capability 的既有 MUST 可能与本次齐全时跳过 update 的行为存在张力 → 本 change 不触碰那些 spec，另立后续规范裁决任务。
