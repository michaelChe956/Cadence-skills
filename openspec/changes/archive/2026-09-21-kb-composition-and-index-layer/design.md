# Design

## 关联

完整设计已确认并持久化于 `cadence/designs/2026-09-20_方案设计_KnowledgeBase组合与索引层_v1.0.md`；本文件记录契约层边界与权衡。

## 边界与决策

### 两通道生成，禁止枚举

- CAP 实体只有两个合法出生通道：api-scope 用户诉求（proposed）、已有聚合端点反向建立（可 verified）。会话候选、名称相似、字段同名、共同 userId 均不构成生成依据——组合发现与会话级候选永不落库。
- 状态机 `proposed/verified/retired` 与 2a 的 `ai-draft/confirmed` 正交：前者描述"设计→实现→退役"，后者描述"证据→人工核准"。

### relation-graph 是投影不是真相源

- 唯一真相源仍是矩阵与领域文档；图 = 矩阵的机读投影（derived_from 显式声明）。
- 防漂移三件套（复刻配置指纹三重相等模式）：严格派生（禁手工编辑）+ 同一次原子写入重建 + global-validation 第 6 项等值校验。
- 定位：只服务导航（种子命中 + 一跳邻域）；证据与审计仍回矩阵/领域文档。图缺失时降级旧 README 链，只损失效率不损失正确性。

### 横向解禁的分域授权

- 词表横向 3 类由"禁写"改"已启用（2b）"，但唯一写入方限定为组合层（Overview 通道）；api/pages 的写入行仍限纵向枚举——防止解禁后横向边从错误入口流入。
- JOIN_KEY 证据纪律复用 api §7.1 端到端映射的既有证据链，不发明新证据类型。

### 漂移分级不加状态

- 在既有 `基线漂移` 状态内部分级（普通→有条件就绪 / 关键失效→阻断），不扩枚举；判定条件写死为可操作清单（删除/废弃、契约字段、鉴权、JOIN_KEY 跳）。
- 不新增落盘出口：十三节内呈现 + 既有 task-contexts/ 保存路径。

### Update 原子性

- 横向重算、锚点复核、图重建与既有领域更新同一原子提交；失败零部分写入沿用现有机制。

## 失败处理

| 失败 | 处理 |
|------|------|
| 图与矩阵等值校验失败 | global-validation 判 failed，保持可续跑 |
| 输入 API 删除/废弃 | CAP 标待确认或 retired，不留断链 verified |
| JOIN_KEY 映射跳缺失 | 边标待确认、组合不得 verified |
| 图缺失 | context 降级 README 链并留痕 |

## 兼容性

- Schema 4.0 不变；capabilities/ 为可选域（空目录合法）；无诉求无聚合端点的项目行为与前两批完成态完全一致。
- 不触碰：原子写入、幂等、脱敏、非推测、ai-draft/confirmed、初始化状态机。
