# Design

## 关联

完整设计已由用户确认并持久化于 `cadence/designs/2026-09-20_方案设计_KnowledgeBase关系契约与检索修复_v1.0.md`；本文件记录契约层必需的架构边界与权衡结论。

## 边界与决策

### 所有权

- 矩阵模板与关系词表 Owner 为 `knowledge-base-base-info`（第一个建立关系矩阵的 Skill），存放于其 `assets/`；api/pages/bootstrap/context/overview 交叉引用，不各自复制副本。
- 单一 Owner 与现有区块所有权惯例一致（API 导航区块归 api Skill、页面导航区块归 pages Skill）。

### 关系词表：一次定全，分批启用

- 词表一次定义全部 11 类（纵向 8 + 横向 3），横向 3 类标注"第二批启用"——避免第二批能力组合层落地时再次修改同一份契约文件。
- 定义枚举值不等于授权使用：横向类型在第一批无任何合法写入路径，由词表文件本身的批次标注与 global-validation 枚举检查双重约束。
- 方向原则：与既有领域文档链路方向一致——调用/访问链取"消费方 → 提供方"（API → SERVICE/MODULE → TABLE）；表文档 §8 的反查关联保持原方向 TABLE → API/PAGE（`CONSUMED_BY`）。原 base-info §8 的"逻辑表 → 读服务与写服务"拆为 `READS`/`WRITES` 有向边，语义映射表写入词表文件保证旧表述可追溯。

### 机械检查复用既有模式

- global-validation 第 5 项复用现有"来源文件键数 == 文档收录键数"的机械比对模式：表头六列 + 逐行关系类型 ∈ 词表。检查失败沿用现有失败处理（保持 `in_progress`、只报告缺失项、不删产物）。

### 精确种子直取不破坏留痕

- 直取必须在第 2 层证据摘要记录"精确种子直取"与种子值，维持"每层必须输出本层证据摘要"的硬门禁；候选无法唯一定位时回退完整索引路径。

### 陈旧度只做可见，不做自动失效

- 表模板两字段必填 + overview README 暴露，是纯产物层改动；不给 context 开知识库写权限，不引入漂移自动落盘（context 漂移出口属第二批）。Update 变更包仍是唯一刷新入口。

## 失败处理

| 失败 | 处理 |
|------|------|
| 词表外关系类型 | 拒绝写入该行 + 登记待确认（不阻断其他行） |
| global-validation 矩阵检查失败 | 判 `failed`，保持可续跑状态，不删除产物 |
| 精确种子无法唯一定位 | 回退完整索引路径并记录回退原因 |
| 表文档漂移字段为空 | base-info 完成条件不满足，阶段不得完成 |

## 兼容性

- Schema 保持 4.0；无新初始化阶段、无新顶层目录、无 Manifest 顶层域变更。
- 本仓库与消费项目无存量 Schema 4.0 实例，无迁移成本；新初始化直接按新契约生成。
- 不触碰：原子写入、变更包幂等、敏感脱敏、初始化状态不变量门禁。

## 权衡记录

| 备选 | 弃用原因 |
|------|---------|
| 模板放 bootstrap/assets | bootstrap 是编排者但不写矩阵，Owner 与产物分离，违反区块所有权惯例 |
| 词表只定纵向 8 类 | 第二批必须再开变更改同一契约文件，两次评审同一文件 |
| context 漂移出口并入本批 | 第一批将跨 5 个 Skill 且动 context 行为；漂移出口与第二批 CAP/边表一起动 context，一次变更动一个 Skill |
