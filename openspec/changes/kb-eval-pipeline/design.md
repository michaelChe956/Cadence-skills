# Design

## 关联

完整设计已确认并持久化于 `cadence/designs/2026-09-20_方案设计_KnowledgeBase自动化测试体系_v1.0.md`；本文件记录契约层边界与权衡。

## 边界与决策

### 对齐而不依赖 rule-eval-p0

- 共享约定：车道语义（Tier-0/1/2）、报告路径（cadence/reports/eval/）、熔断参数风格、具名 diff 报告形态。
- 不共享代码：rule-eval-p0 未实施，kb-eval 先行；后续落地时抽公共 README 对齐，不强行合并 runner。

### 断言的确定性边界

- 只断三类可机械判定物：结构不变量（与内容无关）、具名锚点（fixture 埋点已知→期望具名）、反例（禁止项）。
- 不断 LLM 措辞、顺序、行号。判分不读 agent 自述，只读产物文件与 transcript 工具调用记录。
- 断言器自测（损坏样本必红）是 Tier-0 的一部分——断言器失效比缺测试更危险（假绿）。

### 阶段化 = 测试执行器与 skill 状态机的同构

- 每阶段一个 agent 会话、产物落盘、断言后前进——与 `coverage.initialization` 阶段机同构；results.json 与状态机双保险（防 agent 未如实登记状态时误跳阶段）。
- 单阶段重跑（--stage）是成本控制核心：skill 修复后只重跑受影响阶段。

### fixture 是资产不是用后即弃

- git 管理 + 埋点说明登记（埋点→机制→断言编号对照）；过拟合对策：具名断言锚定"机制生效证据"而非精确文本，季度审视。

## 失败处理

| 失败 | 处理 |
|------|------|
| 阶段断言失败 | 即停留 transcript；results.json 记录；修复后 --stage 续跑 |
| 熔断触发 | 终止并保留已完成部分，可续跑 |
| 断言疑似不合理 | 走设计评审改期望，附记录 |

## 兼容性

- 纯新增 evals/kb/；不修改任何 skill（首期）；报告为运行时产物。
- 依赖：Python3+PyYAML、headless agent 会话（首期单端）。

## 权衡记录

| 备选 | 弃用原因 |
|------|---------|
| 幂等双跑 byte-identical | LLM 产物非确定性；改为结构不变量双跑 |
| 轨迹断言（探针判 stream-json） | KB 阶段无统一轨迹格式；首期产物+transcript 抽查，多端矩阵化留给 rule-eval-p0 共建 |
| PR 车道直接接 Tier-1 | 全链 $2–5/轮不可 PR 化；Tier-0 先行具备零成本接入性 |
| 真实开源项目做 fixture | 不可控、范围大；自造全埋点可控，真实项目留作第二轮 |
